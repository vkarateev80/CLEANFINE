# Проверенные факты проекта Cleaning Ops

Единая спека фактического состояния системы. Собрана по итогам М6 и М7 и содержит только то,
что **проверено запуском, измерением или чтением кода** — не пересказ спецификаций. Там, где
утверждение взято из документации, а не из наблюдения, это помечено.

Как пользоваться: перед работой с сервисом или экраном сверяйтесь с разделом 3 (контракты API)
и разделом 5 (ловушки среды). Большинство этих фактов стоило часов отладки; они собраны здесь,
чтобы не стоило их дважды.

## 3. Контракты API — фактические, снятые с кода и живыми запросами

| Эндпоинт | Факт |
|---|---|
| `POST /api/auth/login` | отвечает **201**, а не 200 |
| `GET /api/chat/chats` | отдаёт **голый массив**, а не `{ items }` — единственная такая асимметрия в проекте |
| Поля чата | `id, type, title, objectId, ticketId, createdAt, lastMessage, unreadCount`. **`title` бывает `null`**; **поля участников нет вовсе** |
| Поля сообщения | `id, chatId, authorId, text, attachmentIds, createdAt` — **имени автора нет**, только id |
| Чат по WebSocket | namespace **`chat`**, токен в **`auth.token`** handshake (основной путь), `?token=` — запасной; события клиента `message:send`, `message:read`; при невалидном токене соединение отклоняется с `unauthorized` |
| `POST /api/notifications/device` | тело `{ token, platform }`, где `platform` строго `android` \| `ios` \| `web`; отвечает **200**, не 201 |
| `GET /api/notifications` | `{ items, total, page, limit, unreadCount }` |
| `PATCH /api/notifications/settings` | тело `{ disabledTypes: [...] }` — типы, от которых пользователь **отказывается**. Семантика **обратная** состоянию тумблера: инвертировать и при чтении, и при записи |
| Аварийная заявка | только `POST /api/tickets/emergency`; через `POST /api/tickets` её создать нельзя |
| `POST /api/users` | обязательны `email`, `password`, `fullName`; `role` из `OPERATOR`\|`SUPERVISOR`\|`ADMIN`\|`CLIENT` |
| `POST /api/objects` | обязательны `name`, `address`, `lat`, `lng`, `type`, `totalArea`, `floorsCount`, `clientName`, `clientContact` |
| Отчёты (М7.1) | `/api/{materials,tickets,schedule,gps}/reports/<отчёт>`; представления живут **внутри** сервисов-владельцев данных |

**Пуш:** в разработке при пустых `FIREBASE_*` поднимается `MockPushSender`, поэтому весь путь
push проверяется без реальных ключей. Заводить их не нужно.

## 4. Дефекты, найденные и исправленные (с механизмом)

1. **`POST /api/chat/chats` → 500.** У `Chat.objectId` глобальный уникальный индекс, а ticket-чат
   писал туда объект заявки. Вторая заявка того же объекта давала `P2002`, `isUniqueViolation`
   уводил в ветку «гонки», где чат по `ticketId` не находился → `NotFoundError` → 500.
   Исправлено: ticket-чат не заполняет `objectId`, ветки гонки используют `findUnique` с rethrow,
   миграция + CHECK-ограничение.
2. **Приложение не запрашивало разрешения геолокации.** В `AndroidManifest` не было
   `ACCESS_FINE_LOCATION`/`ACCESS_COARSE_LOCATION`, а `geolocator_android` их намеренно не
   декларирует. Итог на устройстве: диалог не появляется, точки не пишутся, геозона при
   `check-in` не проверяется — **смена оператора не открывалась вообще**. Автотесты не видели,
   потому что работают на подменах.
3. **Адреса файлов с петлевым хостом.** `planImageUrl` и ссылки фото/аватара/вложений отдавались
   с `localhost`, что верно в браузере на той же машине, но на телефоне `localhost` — само
   устройство. Итог: карта маршрута показывала заглушку вместо плана этажа. Исправлено
   приведением петлевого хоста к хосту API (`ApiConstants.deviceUrl`).
4. **GIST-индексы М3.1 не использовались вообще.** Предикаты приводили колонку к `::geography`,
   а индексы были по geometry → условие уходило в `Filter`: «сотрудники поблизости» 2400 мс
   с отбрасыванием 35 468 строк. После индексов по выражению — 378 мс. **Дефект функциональный,
   а не только производительный:** страдали SOS-вертикаль и валидация входа на объект.
5. **Мёртвый консьюмер RabbitMQ** в material-service: 18 необработанных событий, ноль
   подписчиков, в логе тишина — не работало сквозное автосписание материалов.
6. **Композер портала под фиксированной панелью навигации** — сообщение нельзя было отправить.
7. **OOM-kill Postgres под эмуляцией:** JIT давал 14,7 с вместо 9 мс на тяжёлом агрегате.
   Закрыто `jit=off`.
8. **Причина пятисекундных таймаутов под нагрузкой — ретранслятор, а не сервис.** nginx открывал
   новое TCP-соединение на каждый запрос; при 100 rps он переставал принимать новые. Исключено
   измерениями: сервис напрямую давал p95 6,7 мс и 0 ошибок. **Урок: убедись, что меряешь
   систему, а не транспорт перед ней.**

## 5. Ловушки среды и кода — читать до начала работы

### Стенд и инфраструктура

- **Сервисы умирают вместе с процессом-родителем.** Запускать их нужно управляемой фоновой
  задачей (`stand.sh serve`), иначе через время стенд молча ложится и все проверки дают ложный
  результат.
- **Vite слушает `localhost` (IPv6) и недоступен по `127.0.0.1`.** Веб-набору e2e Vite
  обязателен: без него прогон даёт ложную картину (2 из 45 вместо 45).
- **Prisma и IPv6.** Серверные адреса в `.env` используют `127.0.0.1`, а не `localhost`
  (исключения: `MINIO_ENDPOINT`, `VITE_WS_URL`).
- **`docker exec` в контейнер Postgres.** Образ amd64 под эмуляцией; если в VM не зарегистрирован
  `qemu-x86_64`, любой `docker exec` падает с `exec format error`, уборка тестов пропускается
  (8 наборов вместо 1), и мусор прошлых прогонов роняет соседние тесты. Лечение — `colima restart`;
  проверка — `colima ssh -- ls /proc/sys/fs/binfmt_misc/`.
- **`scripts/reset-stand.sh` стирает и демонстрационные данные.** После него восстанавливать
  строго в порядке: аккаунты (`POST /api/users`) → объект (`POST /api/objects`) → `seed.mjs`.
  Сам сид объекта не создаёт и падает, если его нет.
- **В macOS нет `timeout`.** Для ограничения времени команды: `perl -e 'alarm shift; exec @ARGV' N <команда>`.

### Мобильное приложение

- **drift + fake-async.** `StreamQueryStore.close()` синхронно ждёт таймера, который во
  fake-async срабатывает только при `tester.pump()`. Отписка от drift-потока после последнего
  `pump` приводит к вечному ожиданию в `database.close()`. Уборка обязана жить **в теле теста**
  (`finally`) и дренировать очередь: `test/helpers/screen_harness.dart`.
- **`path_provider` нельзя ждать на критическом пути отрисовки** — в тестах не завершается
  никогда, экран навсегда остаётся в загрузке. Файловые операции — фоном и best-effort.
- **`ref.mounted` у `AsyncNotifierProviderRef` не существует.**
- **Окно теста по умолчанию 800×600** — ленивый `ListView` не строит пункты ниже сгиба; для
  длинных экранов окно расширять (например, 800×2400).
- **Диагностический признак зависания:** процессы `flutter_tester` живы, CPU у них **ноль**,
  время идёт. Ждать бессмысленно — прогон не завершится.

## 7. Процесс и инструменты

- **Один тип — один документ в реестре оркестра.** Новая версия того же типа **вытесняет**
  предыдущую: писать «отдельный task_spec на каждую веху» нельзя, иначе действующей останется
  только последняя. Остаток плана ведётся одним живым документом.
- **Разрешения токена.** У используемого токена нет scope `workflow`: `git push` с изменениями
  в `.github/workflows/**` отклоняется. Файлы workflow правятся через Contents API или веб-интерфейс;
  в этом репозитории правок workflow не потребовалось ни для одной вехи.
- **Git-операции — только у оркестратора.** Исполнителям запрещено коммитить, пушить и создавать
  ветки: изменения остаются в рабочем дереве и фиксируются отдельно.
- **Проверка результата — лично оркестратором**, а не по отчёту исполнителя. За проект трижды
  случалось, что исполнитель сдавал работу с неработающим кодом или без требуемых тестов; в одном
  случае он сообщил об успехе, не выполнив главного требования вехи.
- **Смена исполнителя после двух провалов себя оправдывает:** свежий контекст находил корневую
  причину там, где предыдущий дважды латал симптомы.

## 8. Что осталось незакрытым

- **М7.5 (прод-инфраструктура)** и **М7.6 (финальный смоук и релиз v1.0.0)** — не начаты.
  Terraform и k8s-манифесты можно написать и проверить на синтаксис, но развернуть их физически
  негде: нет ни кластера, ни сервера, ни доступа к домену.
- **Подписанный IPA для iOS невозможен** без платного Apple Developer Program либо подключённого
  iPhone: в Xcode доступна только бесплатная Personal Team, сертификатов подписи и устройств нет.
  Сборка под симулятор при этом собрана и запущена.
- **Открытые пункты, не блокирующие релиз:** `complete` принимает любой `operationId` без сверки
  с техкартой; портал определяет «свой объект» эвристикой по `clientName`; эндпоинта
  `DELETE /device` нет — устройство не отписывается при выходе; KPI gps-сервиса считает
  `staff_route_activity` по всей таблице `gps_tracks` (439 мс на текущем объёме); тип таблиц
  различается между сервисами (PascalCase у material/schedule, snake_case через `@@map` у ticket).
