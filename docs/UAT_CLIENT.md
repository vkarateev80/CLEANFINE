**Веха:** М7.4 «UAT и исправления» · **Сценарий:** клиент видит только свой объект,
создаёт заявку, общается в чате.

`frontend/web-client` за nginx), API через единую точку входа `http://127.0.0.1:8080/api`.
**Роль играет:** реальный демонстрационный клиент `owner@cleanfine.ru` (роль `CLIENT`,
ФИО **«ООО «Ромашка»»**, пароль — `~/.cleaning-ops/owner-account.txt`).
**Прогон:** `cd test && node uat/uat-client.mjs` · **Сырой протокол:** `test/uat/results/client.md`
**Дата прогона:** 21.09.2026, 11:47–11:49 MSK.

## Наблюдения, не ставшие дефектами

1. **Портал не рендерит чат заявки.** Ответы менеджера по заявке клиент читает через
   `GET /api/chat/messages/search`, а в интерфейсе портала видит только прямой чат с
   менеджером. Это соответствует реализации М5.4 (портал открывает самый свежий
   `DIRECT`-чат) и зафиксировано в `test/README.md` как ограничение набора, но как
   пользовательский сценарий «обсудить заявку в её чате» порталом не поддержано.
   **Severity: косметический** (функция доступна в прямом чате), дефект D-6.
2. **Первое сообщение в чате отправляется только оптимистично** при живом
   WebSocket: до правки стенда (см. D-1 в `docs/UAT_PROTOCOL.md`) сокет не
   поднимался, и портал уходил в REST-фолбэк — сообщение всё равно доходило, но
   входящие сообщения в реальном времени не появлялись.
