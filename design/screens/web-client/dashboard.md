# 🏢 Экран: Статус объекта (`dashboard`) — главная портала

> DS-004 (М5.5) → реализация в М5.4 (`frontend/web-client/src/pages/Dashboard/DashboardPage.tsx`).
> Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)), не бинарный макет.
> Роль — `CLIENT`; данные — только по своему объекту (см. [`overview.md`](./overview.md) п. 2.1).
> Данные: `GET /api/objects/:id` (core), `GET /api/tickets?objectId=&take=5` (tickets),
> `GET /api/schedule/events?objectId=&date=` (schedule), `GET /api/materials/stocks?objectId=` (materials).
> Источник требований — `docs/agents/DESIGN_SYSTEM.md` → DS-004 («dashboard — Статус объекта»),
> `ПЛАН.md` М5.4 (`/dashboard` — статус своего объекта: core).

## 1. Назначение

Единственный экран, который клиент открывает «просто посмотреть, как дела». Он отвечает на три
вопроса без перехода в другие разделы:

1. **Что сейчас с объектом** — статус (`ACTIVE`/`PAUSED`/`ARCHIVED`), адрес, площадь, этажность.
2. **Что делается** — ближайшие смены и последние заявки с их статусами.
3. **Нужно ли что-то от клиента** — заявки, ожидающие его реакции (выполнены/проверены), и
   непрочитанные сообщения менеджера.

Экран не редактирует объект: правок в портале нет (кроме заявки), у каждой плитки есть переход в
соответствующий раздел.

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL | `/dashboard` (М5.4); `/` редиректит на `/dashboard` |
| Пункт меню | «Статус» — первый пункт нижнего таб-бара [`ClientLayout`](./overview.md#3-маршруты-и-каркас) |
| Guard | `AuthGuard` + `RoleGuard roles={['CLIENT']}` на родительском маршруте `'/'` |
| Чтение | объект клиента (`GET /api/objects/:id`), заявки объекта, смены объекта, остатки по объекту |
| Запись | нет (создание заявки — на [`tickets.md`](./tickets.md)) |
| Чужие данные | `403` → экран «Нет доступа к объекту» п. 6, **не** баннер «Повторить» |

## 4. Состав блоков и порядок

### 4.1. Шапка объекта

| Элемент | Источник | Формат |
|---|---|---|
| Название объекта | `Object.name` | `h1`, `text-xl font-semibold text-neutral-900 sm:text-2xl` |
| Бейдж статуса | `Object.status` | `ObjectStatusBadge` из `components/ui/Badge.tsx`: `ACTIVE` — success, `PAUSED` — warning, `ARCHIVED` — neutral (подписи — `OBJECT_STATUS_LABELS`, `shared/types/core.ts`) |
| Адрес | `Object.address` | `text-sm text-neutral-500`, перенос по 2 строкам (`line-clamp-2` + `title`) |

Статус `ARCHIVED` дополнительно даёт баннер `bg-neutral-100 text-neutral-600`:
«Объект в архиве. Обслуживание приостановлено» — чтобы клиент не строил ожиданий по сменам.

### 4.2. Паспорт объекта

Сетка `grid grid-cols-2 gap-x-4 gap-y-3 sm:grid-cols-4` (на телефоне 2 колонки, на планшете 4);
подпись — `text-xs text-neutral-500`, значение — `text-sm text-neutral-900`, числа — `font-mono`.

| Поле | API | Формат | Отсутствие данных |
|---|---|---|---|
| Тип | `type` | текст | «—» |
| Общая площадь | `totalArea` | `font-mono`, 1 знак, «м²» | «—» |
| Этажей | `floorsCount` | `font-mono` | «—» |
| Помещений | Σ `floors[].rooms` из `GET /api/objects/:id/detail` (если загружаем деталь) | `font-mono` | блок не рендерится |
| Следующая уборка | ближайшая `plannedStart` из смен объекта, где `status = planned` | `font-mono`, `dd.MM HH:mm` | «не запланирована» (`text-neutral-400`) |
| Последняя уборка | максимальный `checkOutAt` завершённой смены | `font-mono`, `dd.MM HH:mm` | «нет данных» |
| Телефон менеджера | контакт из профиля менеджера по чату (М5.1) | ссылка `tel:`, `text-primary-600` | блок не рендерится |

Правило: **никаких пустых строк с прочерком на пол-экрана** — если данных нет, блок не показываем.
Координаты `lat`/`lng` и «Открыть в картах» на главной клиента не выводятся: на телефоне это
открывает карту и уводит из портала; ссылка остаётся в админке (`object_detail.md` п. 4.2).

### 4.3. KPI-плитки (2×2 на телефоне)

| Плитка | Значение | Источник | Переход |
|---|---|---|---|
| Открытые заявки | число заявок объекта со статусами `new`, `assigned`, `in_progress`, `paused`, `overdue` | `GET /api/tickets?objectId=&take=1` по каждому статусу **или** один запрос на статус `new,assigned,in_progress,paused,overdue` и `total` | `/tickets?status=open` |
| Выполнено за 30 дней | число заявок со статусом `completed`/`verified`/`closed` за 30 дней | `GET /api/tickets?objectId=&status=…&take=1` (по `total`) | `/tickets?status=done` |
| Ближайшая смена | `dd.MM HH:mm` | ближайший `ScheduleEventEntity` объекта | `/reports` (там расписание смен) |
| Непрочитанных сообщений | число | chat-service (М5.1/М5.2) или `GET /api/notifications?unreadOnly=true` | `/chat` |

Плитка: `rounded-xl border border-neutral-200 bg-white p-4 shadow-sm`, подпись
`text-xs text-neutral-500`, значение `text-2xl font-semibold text-neutral-900 font-mono`.
Акцентная плитка (например «Открытые заявки» при значении > 0) — `bg-primary-50` + подпись
`text-primary-700`; мягких статусных заливок не используем (их нет в токенах).

### 4.4. Ближайшие смены

Список до 3 ближайших смен объекта (`GET /api/schedule/events?objectId=&from=<сегодня>`), элементы
отсортированы по `plannedStart`.

| Элемент | API | Формат |
|---|---|---|
| Дата и время | `plannedStart` | `font-mono`, `dd.MM HH:mm` (`text-sm text-neutral-900`) |
| Название графика | `scheduleName` | `text-sm text-neutral-500`, обрезка одной строкой |
| Статус | `status` | `Badge`: `planned` — info, `in_progress` — warning, `completed` — success, `missed` — danger (подписи — `SCHEDULE_EVENT_STATUS_LABELS`, `@cleaning-ops/shared/types/schedule`) |
| Факт прихода | `checkInAt` | `text-xs text-neutral-400` «приступили 08:04», если есть |

Строка: `flex items-center justify-between gap-3 border-b border-neutral-200 px-4 py-3 last:border-b-0`.
Клик → `/reports` (расписание смен объекта; отдельного экрана смены в DS-004 нет).
Пусто → `EmptyState` «Уборок пока не запланировано», подсказка «Менеджер добавит график».

### 4.5. Последние заявки

До 5 последних заявок объекта (`GET /api/tickets?objectId=&take=5`), заголовок блока с кнопкой
`Button variant="ghost" size="sm"` «Все →» на `/tickets`.

| Элемент | API | Формат |
|---|---|---|
| Номер | `id` (короткий префикс 8 символов, `font-mono text-xs text-neutral-400`) | человекочитаемого номера в схеме нет — используется префикс UUID (открытый вопрос п. 10.2) |
| Описание | `description` | `text-sm text-neutral-900`, одна строка (`truncate`) + `title` |
| Тип | `type` | `TICKET_TYPE_LABELS` (`types/tickets.ts`): «Плановая»/«Внеплановая» |
| Статус | `status` | `Badge`: `new` — info, `assigned`/`in_progress` — warning, `completed`/`verified`/`closed` — success, `paused` — neutral, `rejected`/`overdue` — danger (подписи — `TICKET_STATUS_LABELS`) |
| Дата создания | `createdAt` | `font-mono text-xs text-neutral-500`, `dd.MM` |

Клик по строке → `/tickets/:id`. Пусто → `EmptyState` «Заявок пока нет» + `Button variant="primary"`
«Создать заявку».

### 4.6. Плавающая кнопка «Создать заявку»

`sticky bottom-[calc(4.5rem+env(safe-area-inset-bottom))]` (над таб-баром) либо закреплена в правом
нижнем углу на `≥1024 px`; `Button variant="primary" size="lg"` + иконка `+`, `w-full sm:w-auto`,
`shadow-lg`. Ведёт на `/tickets/new` (та же форма, что в [`tickets.md`](./tickets.md) п. 7.1).

## 6. Состояния экрана

| Состояние | Триггер | Отображение |
|---|---|---|
| Загрузка (первая) | `isLoading` объекта | скелетон: строка заголовка `h-6 w-2/3`, карточка паспорта `h-24`, 4 плитки `h-20`, 2 строки списка — все `animate-pulse rounded-md bg-neutral-200` |
| Загрузка KPI отдельно | объект уже есть, счётчики грузятся | в плитке вместо числа — `h-6 w-10 animate-pulse bg-neutral-200`; высота плитки фиксирована, вёрстка не «прыгает» |
| Пусто: смен нет | `events.length === 0` | `EmptyState` «Уборок пока не запланировано» + подсказка «Менеджер добавит график» |
| Пусто: заявок нет | `total === 0` | `EmptyState` «Заявок пока нет» + `Button variant="primary"` «Создать заявку» |
| Пусто: объект не привязан | клиент валиден, но `objectId` не определён | `EmptyState` «Объект не подключён», подсказка «Обратитесь к менеджеру: объект ещё не привязан к вашей учётной записи», кнопка «Выйти» |
| Ошибка сети / 5xx | `isError` | `ErrorBanner` «Не удалось загрузить данные объекта» + «Повторить»; каждый блок со своим баннером, чтобы частичный сбой не гасил экран |
| Частичный сбой | объект загружен, KPI/смены нет | паспорт отрисован, в блоке — `ErrorBanner` с «Повторить» (приём `object_detail.md` п. 6) |
| **403** | объект не принадлежит клиенту | отдельный экран: `EmptyState` «Нет доступа к объекту» + `SoftWarning` «Данные доступны только по вашему объекту» + `Button variant="secondary"` «Выйти»; редирект на `/dashboard` без «Повторить» (повтор не изменит ответ) |
| Объект в архиве | `status === 'ARCHIVED'` | баннер `bg-neutral-100 text-neutral-600`; блок смен заменяется `EmptyState` «Обслуживание приостановлено»; кнопка «Создать заявку» остаётся (аварийные ситуации клиент должен уметь сообщить) |
| Объект приостановлен | `status === 'PAUSED'` | `SoftWarning` «Обслуживание приостановлено до {updatedAt}» + те же данные |
| Офлайн | нет сети, есть кэш | `SoftWarning` «Нет соединения — данные могут быть устаревшими» (см. [`overview.md`](./overview.md) п. 5) |

## 8. Данные из API

| Запрос | Назначение | Ключевые поля |
|---|---|---|
| `GET /api/objects/:id` | шапка и паспорт | `name`, `address`, `type`, `totalArea`, `floorsCount`, `status`, `updatedAt` |
| `GET /api/objects/:id/detail` (опционально) | счётчик помещений | `floors[].rooms` |
| `GET /api/tickets?objectId=:id&take=1&status=…` | KPI-счётчики | `total` |
| `GET /api/tickets?objectId=:id&take=5` | последние заявки | `id`, `description`, `type`, `status`, `createdAt` |
| `GET /api/schedule/events?objectId=:id&from=YYYY-MM-DD` | ближайшие смены | `plannedStart`, `scheduleName`, `status`, `checkInAt`, `checkOutAt` |
| `GET /api/materials/stocks?objectId=:id&onlyLow=true` (опционально) | предупреждение «материалы ниже порога» (P2) | `items.length` |
| chat-service / `GET /api/notifications?unreadOnly=true` | счётчик непрочитанных | `total` |

Счётчики KPI: если бэкенд не поддерживает `status` списком, делаем 5 параллельных запросов
(`new`, `assigned`, `in_progress`, `paused`, `overdue`) с `take=1` и суммируем `total` — TanStack
Query выполняет их параллельно, стоимость запроса мала (открытый вопрос п. 10.4).

## 9. Мобильная адаптация

| Диапазон | Поведение |
|---|---|
| `320–359 px` | KPI-плитки в одну колонку (`grid-cols-1`), `p-3`, заголовок `text-lg` |
| `360–639 px` (**основной**) | KPI `grid-cols-2 gap-3`, паспорт `grid-cols-2`, один столбец карточек, `p-4` |
| `640–1023 px` | паспорт `grid-cols-4`, KPI `grid-cols-4`, карточки по 2 в ряд (`sm:grid-cols-2`) для смен и заявок |
| `≥1024 px` | таб-бар → меню в header; контент `max-w-screen-md mx-auto`; плавающая кнопка у правого нижнего угла |

Дополнительно: sticky-заголовок не делаем (на телефоне занимает драгоценную высоту); статус
объекта виден в первой же строке; плавающая кнопка не перекрывает последнюю строку списка — у
`main` есть нижний отступ `pb-[calc(4.5rem+env(safe-area-inset-bottom))]` плюс `pb-20` под кнопку.

## 10. Ограничения и открытые вопросы

1. **Определение «своего объекта»** — см. [`overview.md`](./overview.md) п. 10.1: у `User` нет
   ссылки на объект. До решения экран не может выбрать, какой `objectId` грузить.
2. **Человекочитаемый номер заявки.** В схеме ticket-service номер не хранится; префикс UUID
   (`S-1042` в схеме экрана) — условность спецификации. Предложение: короткий номер на бэкенде
   (последовательность) либо отказ от номера и показ даты + первых слов описания.
3. **KPI «Выполнено за 30 дней»**: фильтра по диапазону дат в `GET /api/tickets` нет
   (`ListTicketsQuery` — `skip/take/status/type/priority/objectId/assigneeId`). Либо фильтруем
   клиентом по `completedAt` из полученной страницы (неточно на больших объёмах), либо добавляем
   `from`/`to` в ticket-service — требуется решение.
4. **Счётчики по статусам**: поддержка `status` списком (`?status=new,assigned`) в API не
   заявлена; до неё — N параллельных запросов (см. п. 8).
5. **Нужны ли смены клиенту вообще** (п. 4.4): DS-004 говорит только «статус объекта»; смены
   добавлены, потому что DoD М5 требует, чтобы клиент видел, что уборка идёт. Если решено
   ограничиться заявками — блок убирается, KPI-плитки становятся 2×2 без «Ближайшей смены».
6. **Источник телефона менеджера** (п. 4.2): в `Object` есть `clientContact`, но это контакт
   **клиента**, не менеджера. Нужно решение М5.3 (кто менеджер и где его контакт).

## 11. Критерии приёмки (чек-лист)

- [ ] `/dashboard` открывается только под ролью `CLIENT`; другие роли уходят на `/login`.
