# 📊 Экран: Отчёты (`reports`) — отчёты по объекту

> DS-004 (М5.5) → реализация в М5.4 (`frontend/web-client/src/pages/Reports/ReportsPage.tsx`).
> Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)), не бинарный макет.
> Роль — `CLIENT`; данные — только по своему объекту (см. [`overview.md`](./overview.md) п. 2.1).
> Данные: `GET /api/materials/report?objectId=&from=&to=` (material-service, М4),
> `GET /api/tickets?objectId=&skip=&take=` (ticket-service, М3.7),
> `GET /api/schedule/events?objectId=&from=&to=` (schedule-service, М4.6),
> `GET /api/materials/stocks?objectId=` (material-service).
> Источник требований — `docs/agents/DESIGN_SYSTEM.md` → DS-004 («reports — Отчеты»),
> `ПЛАН.md` М5.4 (`/reports` — отчёты по своему объекту), `docs/agents/FRONTEND_WEB.md` →
> Acceptance Criteria (Web Client): «Просмотр отчетов».

## 1. Назначение

Показать клиенту, **что фактически сделано на его объекте** за период и **сколько это ресурсов
съело**, без доступа к внутренним разделам админки. Три вопроса:

1. **Что сделано** — заявки объекта: сколько создано, выполнено, просрочено (за период).
2. **Когда работали** — смены объекта: сколько смен, сколько состоялось, сколько неявок.
3. **Что израсходовано** — материалы со списанием по объекту за период (агрегат
   `GET /api/materials/report`), плюс позиции ниже порога на складе объекта.

Экран **только для чтения**: ни одной мутации. Это не «полноценная отчётность» М7
(`PlaceholderPage title="Отчёты" phase="М7"` в админке) — здесь клиентский срез по одному объекту.

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL | `/reports` (+ query-строка `?from=&to=&tab=` — состояние восстанавливается при «назад») |
| Пункт меню | «Отчёты» — третий пункт нижнего таб-бара |
| Guard | `AuthGuard` + `RoleGuard roles={['CLIENT']}` |
| Чтение | `GET /api/materials/report` (в material-service на `GET` нет `@Roles`), `GET /api/tickets` (без `@Roles`), `GET /api/schedule/events` (без `@Roles` на `GET`), `GET /api/materials/stocks` |
| Запись | **нет ни одной** — мутаций на экране не существует |
| Чужие данные | `objectId` всегда из сессии; ответ 403 → экран «Нет доступа» (как в [`dashboard.md`](./dashboard.md) п. 6) |

### 2.1. Готовность бэкенда (важно)

| Источник | Статус | Ограничение |
|---|---|---|
| `GET /api/materials/report` | ✅ есть (`api/materials.ts` → `getConsumptionReport`) | принимает `objectId`, `from`, `to`; отдаёт агрегат в rows + totals |
| `GET /api/tickets` | ✅ есть | **диапазона дат нет**: `ListTicketsQuery` — `skip/take/status/type/priority/objectId/assigneeId`. Отчёт «заявки за период» требует либо фильтра `from`/`to` в ticket-service, либо клиентской агрегации (открытый вопрос п. 10.1) |
| `GET /api/schedule/events` | ✅ есть, `from`/`to` поддерживает (`ListEventsQuery`) | отдаёт **смены**, не «отчёт»: агрегаты считаются на клиенте |
| `GET /api/materials/stocks` | ✅ есть | `onlyLow=true` — фильтр «ниже порога» (в DTO `@Type(() => Boolean)`: передавать только `true`) |

Никакого отдельного report-service в проекте нет и М5.4 его не заявляет: экран — клиентская
агрегация по объекту. Если объём данных вырастет, нужен серверный endpoint (п. 10.1).

## 4. Состав блоков

### 4.1. Шапка

| Элемент | Описание |
|---|---|
| Заголовок | «Отчёты» — `h1`, `text-xl font-semibold text-neutral-900 sm:text-2xl` |

### 4.2. Панель периода

| Элемент | Контрол | Поведение |
|---|---|---|
| Дата начала | `input type="date"` (`Input`, `text-base`) | `from`, по умолчанию — первое число текущего месяца |
| Дата окончания | `input type="date"` | `to`, по умолчанию — сегодня |
| Быстрый выбор | чипы: «Текущий месяц», «Прошлый месяц», «30 дней», «90 дней» | заполняют `from`/`to`; активный чип — `bg-primary-50 text-primary-700 border-primary-500` |
| Подсказка о границах | `text-xs text-neutral-400` | «Максимум 366 дней»; при нарушении — `text-danger-600` и кнопка запроса заблокирована |

Ограничения диапазона (проверка на клиенте, до запроса): `from ≤ to`; разница ≤ 366 дней;
`to` не в будущем (данных за будущее нет). Даты уходят в API как `YYYY-MM-DD` (формат
`<input type="date">`, тот же, что в `ListMovementsQuery.from`).

### 4.3. Табы

| Таб | Приоритет | Содержимое |
|---|---|---|
| «Сводка» | P0 | KPI-плитки 2×2 + список последних выполненных заявок |
| «Уборки» | P0 | таблица-список смен объекта за период: дата, график, статус, факт прихода/ухода |
| «Материалы» | P1 | агрегат расхода по объекту (`ConsumptionReport`) + позиции ниже порога |

Табы — как в `object_detail.md` п. 4.3: активный `border-b-2 border-primary-600 text-primary-700`,
неактивный `text-neutral-500 hover:text-neutral-800`. Активный таб хранится в query-строке
(`?tab=materials`), чтобы ссылку можно было отправить менеджеру.

### 4.4. Таб «Сводка»

KPI-плитки (сетка `grid grid-cols-2 gap-3`):

| Плитка | Значение | Источник |
|---|---|---|
| Заявок создано | число заявок объекта с `createdAt` в периоде | `GET /api/tickets?objectId=&take=100` + клиентский фильтр по дате (п. 10.1) |
| Выполнено | число заявок со статусами `completed`/`verified`/`closed` и `completedAt` в периоде | там же |
| Смен проведено | число смен объекта со `status = completed` в периоде | `GET /api/schedule/events?objectId=&from=&to=` |
| Неявок | число смен со `status = missed` | там же |

Плитка: `rounded-xl border border-neutral-200 bg-white p-4 shadow-sm`, подпись `text-xs
text-neutral-500`, значение `text-2xl font-semibold text-neutral-900 font-mono`. Отрицательное
событие (неявки > 0) — значение `text-warning-600` (мягкой заливки `warning-50` в токенах нет).

Ниже — список до 5 последних выполненных заявок карточками (как в [`tickets.md`](./tickets.md)
п. 4.3: номер, описание одной строкой, `Badge`, дата) со ссылкой «Все заявки →» на `/tickets`.
Если выполненных нет — `EmptyState` «За период выполненных заявок нет».

### 4.5. Таб «Уборки»

Плоский список смен объекта за период (`GET /api/schedule/events?objectId=&from=&to=`), на телефоне —
карточками, на планшете и шире — таблицей `Table.tsx` (тот же контент, как в админке).

| Поле | API | Формат |
|---|---|---|
| Дата | `date` | `font-mono`, `dd.MM.yyyy` |
| План | `plannedStart` | `font-mono`, `HH:mm` |
| График | `scheduleName` | `text-sm`, обрезка + `title` |
| Статус | `status` | `Badge`: `planned` — info, `in_progress` — warning, `completed` — success, `missed` — danger (подписи — `SCHEDULE_EVENT_STATUS_LABELS`) |
| Факт | `checkInAt`, `checkOutAt` | `font-mono text-xs`: «08:04 → 09:37»; без `checkInAt` — «не отмечено» (`text-neutral-400`) |
| Исполнитель | `userId` | **не показываем** ФИО (справочник `/api/users` закрыт для CLIENT); только факт «исполнитель назначен / не назначен» |

Итоговая строка под списком: «Смен: {n}, проведено: {k}, неявок: {m}» (`text-sm text-neutral-500`).
Пагинации нет: `ListEventsQuery` отдаёт смены без `skip/take`, диапазон ограничен периодом
(≤366 дней); при большом объёме — открытый вопрос п. 10.2.

### 4.6. Таб «Материалы»

**Расход по объекту** — `GET /api/materials/report?objectId=&from=&to=` (`ConsumptionReport`):

| Колонка / элемент | API | Формат |
|---|---|---|
| Материал | `rows[].materialName` (по `MaterialConsumptionRow`) | `text-sm text-neutral-900` |
| Единица | `rows[].unit` | `text-xs text-neutral-500` |
| Израсходовано | `rows[].consumedQuantity` | `font-mono text-right`, 2 знака |
| Операций | `rows[].operationsCount` | `font-mono text-right` |
| Стоимость | `rows[].cost` | `font-mono text-right`, «₽», 2 знака |
| Итого | `totals.consumedQuantity`, `totals.operationsCount`, `totals.cost` | строка-итог: `border-t border-neutral-200 font-medium` |
| Период | `from`, `to`, `objectId` | подпись под таблицей (`text-xs text-neutral-500`) — подтверждение, что данные именно по объекту клиента |

**Остатки ниже порога** — `GET /api/materials/stocks?objectId=&onlyLow=true` (P1, информационный

## 7. Действия пользователя

| Действие | Триггер | Результат |
|---|---|---|
| Сменить период | даты или чип | перезапрос всех источников с `from`/`to`; query-строка обновляется |
| Переключить таб | таб | `?tab=…`, запросы таба (данные грузятся лениво: таб не запрашивает своё, пока не открыт) |
| Обновить | «Обновить» / pull-to-refresh | `refetch` активного таба и KPI |

| Скачать CSV | 7.4 | файл `.csv` с таблицей активного таба |

### 7.1. Порядок загрузки и приоритет

1. Сначала — **KPI-плитки** (они отвечают на главный вопрос и грузятся из тех же ответов, что
   списки: считать агрегаты из уже полученных страниц дешевле, чем делать отдельные запросы).
2. Затем — список таба.
3. Период по умолчанию — текущий месяц: клиент чаще всего смотрит «как прошёл месяц».

### 7.2. Агрегация на клиенте (вынужденная мера)

Для заявок серверных агрегатов нет, поэтому:

- запрашиваем заявки объекта страницами по 100 (`take` ≤ 100) **до** достижения `total`
  либо до 500 записей (страховочный предел, дальше — предупреждение `SoftWarning`
  «Показаны данные за период не полностью»);
- фильтруем по `createdAt`/`completedAt` в периоде;
- считаем счётчики.

Такая схема точна для типичного клиента (десятки заявок в месяц) и **не масштабируется** — предел
зафиксирован в открытых вопросах (п. 10.1) и виден в UI предупреждением, а не молчаливым
искажением цифр.

### 7.3. Форматирование чисел и дат

- Даты: `dd.MM.yyyy` (`font-mono`), время — `HH:mm`.
- Количества: разделитель разрядов — узкий пробел (`12 400`), дробные — 2 знака.
- Стоимость: `{сумма} ₽`, `font-mono text-right`; в итоге — `font-medium`.
- Пустое значение — «—» (`text-neutral-400`), но не «0»: «нет данных» и «ноль» — разные вещи.

### 7.4. «Скачать CSV» (P2, опционально)

Кнопка `Button variant="secondary"` в шапке таба. Формируется на клиенте (`Blob` + `URL.createObjectURL`),
разделитель `;` (Excel в русской локали), кодировка UTF-8 с BOM, имя файла
`report-{objectName}-{from}-{to}.csv`. Состав колонок — активный таб. Если по решению М5.4
экспорт не нужен — кнопка не реализуется, спецификация сохраняет её как P2.

## 10. Ограничения и открытые вопросы

1. **Фильтр по датам для заявок отсутствует** — агрегация на клиенте (п. 7.2) с пределом 500
   записей. Требуется решение: добавить `from`/`to` (и, в идеале, `groupBy`-агрегаты) в
   ticket-service или смириться с клиентской агрегацией. Без этого отчёт по заявкам неточен на
   больших объёмах, и спецификация это честно показывает пользователю (`SoftWarning`).
2. **Пагинации у смен нет** (`GET /api/schedule/events` возвращает массив без `{ items, total }`) —
   при периоде 366 дней и ежедневных сменах это ~366 строк на телефон; либо ограничить период
   31 днём по умолчанию, либо добавить пагинацию в schedule-service.
3. **Отдельного report-endpoint'а в проекте нет** и в М5.4 не заявлено; экран — композиция
   существующих API. Если заказчик попросит PDF-отчёт с подписью — это новая задача (Backend +
   Design), а не правка экрана.
4. **Названия материалов/графиков** приходят из ответов; переводов нет — показываем как есть
   (кириллица в фикстурах стенда).
5. **Часовой пояс**: `ScheduleEventEntity.plannedStart` — UTC, в UI админки время показывается
   «как есть» (см. комментарий в `types/schedule.ts`). Портал следует тому же правилу; перевод в
   локальную зону объекта — отдельное решение (иначе цифры портала и админки разойдутся).
6. **ФИО исполнителей** клиенту не показываем (справочник `/api/users` — `ADMIN/SUPERVISOR`);
   если бизнесу нужно «кто убирал», требуется отдельное публичное поле в отчёте.
7. **Экспорт CSV** (п. 7.4) — P2: зависит от решения, нужен ли клиенту файл, и от требований к
   формату (CSV против XLSX/PDF).

## 11. Критерии приёмки (чек-лист)

- [ ] `/reports` доступен только роли `CLIENT`; все четыре запроса уходят с `objectId` из сессии.
- [ ] Период по умолчанию — текущий месяц; смена периода меняет и KPI, и списки, и query-строку.
- [ ] Диапазон проверяется до запроса: `from ≤ to`, ≤366 дней, `to` не в будущем; при нарушении — понятное сообщение, запрос не уходит.
- [ ] KPI-плитки («Заявок создано», «Выполнено», «Смен проведено», «Неявок») посчитаны по данным своего объекта и совпадают с содержимым списков.
- [ ] Таб «Материалы» показывает `ConsumptionReport`: строки материалов и итог (`totals`) с подписью периода и объекта; ничего не додумано на клиенте.
- [ ] Мутаций нет: на экране нет ни одной кнопки, ведущей к `POST`/`PATCH`/`DELETE`.
- [ ] Состояния: скелетон, «нет данных за период», нет расхода материалов, ошибка одного источника не гасит остальные, 403 → «Нет доступа», офлайн-предупреждение.
- [ ] При достижении предела клиентской агрегации (500 заявок) показано `SoftWarning` о неполноте данных.
- [ ] Чужие данные: прямой заход с чужим `objectId` в query не даёт данных (значение из URL игнорируется, `objectId` берётся из сессии).
- [ ] На 360 px нет горизонтального скролла; числа и суммы — `font-mono`, не переносятся; табы и чипы прокручиваются, а не ломают вёрстку.
- [ ] Только токены `tokens.css` и компоненты из [`overview.md`](./overview.md) п. 4; новых hex и сторонних библиотек (графиков/экспорта) нет.
