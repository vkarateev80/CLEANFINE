# 🏠 Экран: Сегодня (`today`) — главный экран оператора — DS-002 (М6.3)

> DS-002 → `home_today.fig`; реализация — М6.3
> (`lib/features/home/presentation/pages/home_today_page.dart`).
> Данные: schedule-service (`API_SCHEDULE_URL`, 3008), ticket-service (3005), core-service (3003).
> Источник требований — `ПЛАН.md` М6.3: *«`home_today`: заявки/события оператора на сегодня (из
> schedule-service через REST «мои события», tickets assigned); карточка текущей смены → переход к
> маршруту»*; чек-лист приёмки — «Главный экран работает» (`docs/agents/FRONTEND_MOBILE.md`).

## 1. Назначение

Экран отвечает на три вопроса оператора в начале дня и **даёт одно действие**:

1. «Есть ли у меня смена сегодня и во сколько?» — карточка смены;
2. «Я уже вышел на смену?» — статус `PLANNED`/`CHECKED_IN` + кнопка «Начать смену» / «Закрыть смену»;
3. «Что ещё висит на мне?» — список моих заявок (`assigneeId = me`) с приоритетом и статусом.

Действие: **перейти к маршруту дня** (при открытой смене) либо **открыть смену** (check-in с
проверкой геозоны). Экран не показывает объекты, за которые оператор не отвечает, и никогда не
показывает чужие заявки: `assigneeId` берётся из `GET /api/auth/me`.

### 1.1. Точка входа в навигации

| Что | Значение |
|---|---|
| Маршрут | `/today` — стартовый маршрут shell: сюда ведут `go('/today')` после входа и таб «Сегодня» |
| Кто открывает | вход (`/login`, `/pin`), таб-бар, успешная отправка SOS (возврат), push «новая заявка» |
| Что открывает | `/route/:eventId` (карточка смены), `/sos` (пункт SOS таб-бара), `/chats/:chatId` (заявка), `/offline` (баннер очереди) |
| Guard | авторизация (токен); роль `OPERATOR`/`SUPERVISOR`/`ADMIN` |

## 3. Состав блоков

### 3.1. Шапка

| Элемент | Виджет | Правило |
|---|---|---|
| Заголовок | `AppBar(title: Text('Сегодня · ${objectName}'))` | `objectName` — из `GET /api/objects/:id` смены; если смен несколько или объект не загружен — просто «Сегодня» |
| Дата | `Text('ср, 17 сентября')` | формат `E, d MMMM` локали `ru`; под заголовком, `sizeSM`, `neutral500` |
| Счётчик очереди | `SyncStatusWidget` — иконка `Icons.sync_problem` + число | число = `pending_actions` со статусами `pending`/`failed` (см. [`offline.md`](./offline.md) §3); тап → `/offline` |
| Непрочитанные | `NotificationBellWidget` — `Icons.notifications_none` + `Badge` | источник — `GET /api/notifications?page=1&limit=20&unreadOnly=true` → `unreadCount`; тап → `/chats` (чат-уведомления) либо список заявок |
| Обновление | `RefreshIndicator` вокруг `ListView` | pull-to-refresh: `GET /api/schedule/my`, `GET /api/tickets`, `GET /api/objects/:id` |

### 3.2. Карточка смены (по одной на каждую смену дня)

| Элемент | Источник | Отображение |
|---|---|---|
| Статус | `ScheduleEventView.status` | бейдж по `SCHEDULE_EVENT_STATUS_LABELS`: `PLANNED` → «Запланирована» (`warning600`), `CHECKED_IN` → «Открыта» (`success600`), `CHECKED_OUT` → «Закрыта» (`neutral500`), `MISSED` → «Неявка» (`danger600`) |
| Название | `scheduleName` | `sizeLG`/`weightMedium` |
| Время | `plannedStart` (ISO) + `checkOutAt` | `HH:mm`–`HH:mm`; если `checkOutAt == null` — `HH:mm`–… |
| Объект и адрес | `objectId` → `GET /api/objects/:id` (`name`, `address`) | `sizeSM`, `neutral500` |
| Маршрут | `routeId` → `GET /api/routes/:id` (`name`, `points.length`, `totalEstimatedTimeMin`) | «Маршрут: {name} · {N} помещений · ~{M} мин»; если `routeId == null` — «Маршрут не назначен» |
| Прогресс | локальная таблица `route_points` (drift) | «Пройдено {done} из {total}»; при `total == 0` строки нет |
| Кнопка маршрута | — | «Маршрут» (`PLANNED`, read-only предпросмотр) / «Продолжить» (`CHECKED_IN`) / «Маршрут» (`CHECKED_OUT`, только просмотр) |
| Причина закрытия | `checkOutReason` | если не `null` (авто check-out) — строка `sizeXS` `warning600` |

### 3.3. Блок check-in / check-out

| Состояние смены | Что показываем |
|---|---|
| `PLANNED` | подсказка «Вы ещё не вышли на смену» + кнопка «Начать смену» + «Отметка возможна только в зоне объекта» |
| `CHECKED_IN` | подсказка «Смена открыта в 08:04» + кнопка «Закрыть смену» (вторичная, `OutlinedButton`) + «Маршрут» (основная) |
| `CHECKED_OUT` | «Смена закрыта в 16:10» + кнопка «Посмотреть итоги» (скролл к прогрессу) |
| `MISSED` | «Вы не отметились на смене. Обратитесь к бригадиру.» (без кнопок check-in — сервер уже перевёл смену) |
| Несколько смен в дне | блоки идут по возрастанию `plannedStart`; check-in/check-out показываются только для смены, выбранной как текущая (`CHECKED_IN`, иначе ближайшая по `plannedStart`) |

Проверка геозоны — на сервере: `POST /api/schedule/check-in` сам спрашивает gps-service; клиент
только передаёт координаты из `geolocator`. Если разрешение не выдано — кнопка остаётся, но при
нажатии показывается диалог разрешения, затем «Не удалось определить местоположение» (§4).

### 3.4. Список «Мои заявки»

| Элемент | Источник | Правило |
|---|---|---|
| Запрос | `GET /api/tickets?assigneeId={me}&skip=0&take=20` | ответ `{items, total}`; сортировка сервера — по `createdAt` (`TicketsService.list`) |
| Карточка | `TicketListItem` | приоритет-точка (`critical`/`high` — `danger500`, `normal` — `info500`, `low` — `neutral400`) + `TICKET_TYPE_LABELS`, статус-бейдж по `TICKET_STATUS_LABELS` |
| Описание | `description` | `maxLines: 2`, `TextOverflow.ellipsis` |
| Место и срок | `roomId` (локально из drift: имя помещения), `arrivalDeadline`/`completionDeadline` | «3 этаж, Санузел 101 · до 12:30»; срок — `completionDeadline ?? arrivalDeadline ?? reactionDeadline` |
| Закрытые заявки | `status` в `verified`/`closed`/`rejected` | показываются в конце списка (одна строка), чтобы не засорять экран |
| Тап | — | открыть чат заявки, если он есть (`GET /api/chat/chats` → `chat.ticketId == ticket.id`); иначе — карточка заявки (шторка с деталью из `GET /api/tickets/:id`) |
| «Все →» | — | шторка «Мои заявки» с полным списком и пагинацией (`take` 20) |

Типы `planned`/`unscheduled` в списке оператора появляются от schedule-service (заявка создаётся по
смене, `M4.4`), `emergency` — от SOS других людей, если оператор оказался ближайшим и бригадир его
назначил.

## 4. Действия пользователя

| Действие | Триггер | Результат | Ошибки |
|---|---|---|---|
| Обновить | pull-to-refresh | параллельно: смены, заявки, объект | ошибка сети → баннер, данные остаются из кэша |
| Начать смену | `Key('today_checkin_button')` | `geolocator.getCurrentPosition()` → `POST /api/schedule/check-in {scheduleId, lat, lng}` → статус `CHECKED_IN` | 403 «Вы находитесь вне зоны объекта»; 404 «Смена на сегодня не найдена»; 502 «Сервис геозон недоступен»; нет разрешения → «Не удалось определить местоположение» |
| Закрыть смену | `Key('today_checkout_button')` | подтверждение (`AlertDialog` «Закрыть смену?») → `POST /api/schedule/check-out {scheduleId, lat?, lng?}` | 400 «Смена не открыта: сначала выполните check-in» |
| Открыть маршрут | `Key('today_route_button')` | `/route/:eventId` | если `routeId == null` — snackbar «Маршрут не назначен» |
| Смотреть заявку | тап по карточке | чат заявки или шторка детали | — |
| Открыть очередь | тап по `SyncStatusWidget` | `/offline` | — |
| SOS | пункт SOS таб-бара | `/sos` | — |

Во время запроса кнопка `disabled` и показывает `CircularProgressIndicator` — повторное нажатие не
создаёт вторую отметку (сервер идемпотентен, но UI не должен «мигать» двумя запросами).

## 8. Данные из API

| Запрос | Параметры | Ответ / поля | Использование |
|---|---|---|---|
| `GET /api/schedule/my` | `from=YYYY-MM-DD&to=YYYY-MM-DD` (сегодня) | `ScheduleEventView[]`: `id`, `scheduleId`, `scheduleName`, `objectId`, `routeId`, `date`, `plannedStart`, `status`, `userId`, `checkInAt`, `checkOutAt`, `checkInLat/Lng`, `checkOutLat/Lng`, `ticketId`, `checkOutReason` | карточки смен |
| `GET /api/schedule/events/:id` | — | тот же `ScheduleEventView` | обновление одной смены после check-in/out |
| `GET /api/objects/:id` | — | `Object`: `id`, `name`, `address`, `lat`, `lng`, `type`, `totalArea`, `floorsCount`, `clientName`, `clientContact`, `status` | название объекта в шапке и адрес в карточке |
| `GET /api/routes/:id` | — | `Route` + `points[]` (с `room`) + `totalEstimatedTimeMin` | «N помещений · ~M мин» |
| `GET /api/tickets` | `assigneeId={me}&skip=0&take=20` | `{items: TicketListItem[], total}`; поля `id`, `type`, `priority`, `status`, `objectId`, `roomId`, `description`, `lat`, `lng`, `createdAt`, `reactionDeadline`, `arrivalDeadline`, `completionDeadline`, `_count` | блок «Мои заявки» |
| `GET /api/notifications` | `page=1&limit=20&unreadOnly=true` | `{items, total, page, limit, unreadCount}` | счётчик в шапке |
| `POST /api/schedule/check-in` | `{scheduleId, lat, lng}` | `ScheduleEventView` (статус `CHECKED_IN`) | «Начать смену» |
| `POST /api/schedule/check-out` | `{scheduleId, lat?, lng?}` | `ScheduleEventView` (статус `CHECKED_OUT`) | «Закрыть смену» |
| `GET /api/chat/chats` | — | `ChatSummary[]` (`ticketId`) | поиск чата по заявке для тапа |

Кэш: смены, объект и заявки пишутся в drift (`shift_events`, `cached_tickets`) при каждом успешном
ответе; экран рисует их до сети. TTL — до следующего успешного обновления, но **не более 24 ч**:
просроченный кэш показывается с пометкой «Данные от {дата} {время}».

## 10. Что проверяет widget-тест

1. **Нет смены**: мок репозитория отдаёт `[]` → `find.text('На смену сегодня вы не назначены')`
   находит `Key('today_empty_text')`, кнопка `Key('today_checkin_button')` отсутствует.
2. **Check-in со сменой `PLANNED`**: нажатие `Key('today_checkin_button')` вызывает мок
   `scheduleRepository.checkIn(scheduleId, lat, lng)` ровно один раз, а после ответа со статусом
   `CHECKED_IN` бейдж меняется на «Открыта» и появляется `Key('today_route_button')`.
3. **403 при check-in**: мок бросает `ForbiddenFailure('Вы находитесь вне зоны объекта')` →
   на экране `find.text('Вы находитесь вне зоны объекта')`, статус смены остаётся «Запланирована».
4. **Оффлайн**: при `pending_actions` с двумя записями `Key('today_sync_status')` показывает «2», а
   при отсутствии сети виден текст «Нет соединения — данные могут быть устаревшими».

## 11. Ограничения и открытые вопросы

1. **⚠️ `ScheduleEventView` не содержит `objectName`/`routeName`.** Проекция смены отдаёт только
   `objectId`, `routeId` и `scheduleName` (`schedule.service.ts` → `toView`). Главный экран вынужден
   делать `GET /api/objects/:id` и `GET /api/routes/:id` на каждую смену — N+1 запросов на мобильной
   сети. Требуется добавить `objectName` (и, желательно, `routeName`, `routePointsCount`) в
   `ScheduleEventView`.
2. **⚠️ `Schedule.objectId`/`routeId` nullable**: смена может быть без объекта и без маршрута. Что
   делать оператору (чек-лист без плана? отказ?), в `ПЛАН.md` не сказано. В спецификации — «Маршрут
   не назначен» и недоступная кнопка маршрута; требуется решение владельца.
3. **Смена может не иметь заявки** (`ticketId == null`), если генерация не смогла создать заявку
   (`schedule.service.ts`: «Смена сохранена без ticketId — следующая генерация до-создаст заявку»).
   Тогда чек-лист не сможет отправить завершение операции (`POST /api/tickets/:id/...` требует
   `ticketId`) — на экране маршрута это состояние описано как блокирующее
   ([`checklist.md`](./checklist.md) п. 10.4), но правильнее — до-создавать заявку при check-in.
4. **«Текущая смена» при нескольких сменах** — правило (`CHECKED_IN` → иначе ближайшая по
   `plannedStart`) придумано в спецификации; в API такого понятия нет. Нужно подтверждение.
5. **Счётчик непрочитанных** — `GET /api/notifications` без `type`-фильтра: чат-уведомления и заявки
   смешаны, поэтому тап по «🔔» ведёт в чаты. Отдельного «списка уведомлений» в DS-002 нет (в
   `ПЛАН.md` М6.8 — только push), список — отдельная задача.
6. **Итоги смены** (сколько операций выполнено, были ли пропуски) на экране не считаются из API:
   сервер отдаёт только отметки операций по заявке (`GET /api/tickets/:id`). Источник итогов —
   локальный прогресс маршрута.
