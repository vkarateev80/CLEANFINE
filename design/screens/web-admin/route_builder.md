# 🧭 Экран: Конструктор маршрутов (`route_builder`)

> DS-003 (М2.8) → реализация в М2.7 (`frontend/web-admin/src/pages/Routes/RouteBuilder.tsx`).
> Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)).
> Данные: `routes` CRUD и `route-points` (М2.5), `POST /api/routes/:id/reorder` (М2.5, код — в
> `docs/agents/BACKEND_CORE.md` п. 2), помещения этажа (М2.4), план этажа (М2.3).

## 1. Назначение

Сборка порядка обхода помещений для уборки: слева — список маршрутов этажа, в центре — точки
маршрута с **drag-and-drop переупорядочиванием**, справа — план этажа с нумерованными маркерами.
Сохранение порядка — один вызов `reorder` (транзакционный, с пересчётом оценки времени).
Требование М2.7: «Routes (RouteBuilder: список точек слева, план справа, drag-and-drop
переупорядочивание → вызов `reorder`)».

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL списка | `/routes` — существует: `router/index.tsx`, элемент `routeBuilder` = `RoleGuard roles={['ADMIN']}` + заглушка М2 |
| URL маршрута | `/routes/:id` — **предложено** (в роутере нет); при отсутствии — выбор маршрута состоянием в `/routes` |
| Query-параметры | `?floorId=…` (переход из [`floor_plan.md`](./floor_plan.md)), `?objectId=…` |
| Guard | `RoleGuard roles={['ADMIN']}` — как сейчас в роутере; SUPERVISOR — вопрос (п. 10.5) |
| Пункт меню | «Маршруты» (только ADMIN — уже учтено в `AdminLayout.NAV` через `roles: ['ADMIN']`) |

## 8. Данные из API

### 8.1. Маршрут

`GET /api/routes?floorId=:id` → `{ items: Route[], total }`; `GET /api/routes/:id` → `Route` + `points` + `room`.

| Поле | Тип | Использование |
|---|---|---|
| `id` | uuid | выбор маршрута, `reorder`, маршрут `/routes/:id` |
| `floorId` | uuid | привязка, фильтр по этажу |
| `name` | string | список, заголовок колонки точек |
| `status` | `DRAFT`\|`ACTIVE`\|`ARCHIVED` | бейдж, режим read-only |
| `points[]` | `RoutePoint[]` | список точек (сортировка по `orderIndex`) |
| `createdAt`, `updatedAt` | ISO 8601 | метаданные (P2, `text-xs text-neutral-400`) |

**Оценка времени маршрута** отдельным полем в схеме не хранится: Σ `RoutePoint.estimatedTimeMin`
считается клиентом для отображения, а сервер пересчитывает её при `reorder` (М2.5) и может
возвращать в ответе (п. 10.3).

### 8.2. Точка маршрута

| Поле | Тип | Использование |
|---|---|---|
| `id` | uuid | `pointIds` в `reorder`, ключ строки |
| `routeId` | uuid | принадлежность маршруту (валидация на сервере при `reorder`) |
| `roomId` | uuid | выбор помещения, поиск координат |
| `orderIndex` | number | нумерация `orderIndex + 1`; `@@unique([routeId, orderIndex])` |
| `estimatedTimeMin` | number \| null | поле «оценка времени», Σ в футере |

### 8.3. Помещение и план (для правой колонки)

| Поле (`Room`) | Использование |
|---|---|
| `name`, `zone`, `floorType` | подписи маркера, легенда, select помещений |
| `coordsX`, `coordsY`, `coordsWidth`, `coordsHeight` | позиция маркера и рамки на плане; `null` → маркер в списке без позиции, пометка «нет координат» |
| `techCardId` | индикатор «помещение без техкарты» |
| `Floor.planImageUrl`, `Floor.planScale` | изображение плана, подсказка масштаба |

### 8.4. Запросы

| Действие | Запрос |
|---|---|
| Список объектов/этажей | `GET /api/objects?take=100`, `GET /api/floors?objectId=:id` |
| Список маршрутов | `GET /api/routes?floorId=:id` |
| Создание/изменение/удаление маршрута | `POST /api/routes`, `PATCH /api/routes/:id`, `DELETE /api/routes/:id` |
| Помещения этажа | `GET /api/rooms?floorId=:id&take=100` |
| Добавление/изменение/удаление точки | `POST /api/route-points`, `PATCH /api/route-points/:id`, `DELETE /api/route-points/:id` |
| **Переупорядочивание** | `POST /api/routes/:id/reorder` — тело `{ pointIds: string[] }`; полный список id маршрута в новом порядке. Сервер: транзакция, проверка принадлежности точек маршруту (иначе 400), обновление `orderIndex`, пересчёт оценки времени (М2.5) |

## 10. Открытые вопросы

1. **Библиотека drag-and-drop не выбрана.** Список зависимостей (`docs/agents/FRONTEND_WEB.md` п. 1:
   `react-router-dom`, `zustand`, `@tanstack/react-query`, `axios`, `tailwindcss`, `mapbox-gl`,
   `recharts`) не содержит DnD-библиотеки. Варианты: `@dnd-kit/core` + `@dnd-kit/sortable`
   (рекомендуется: доступность, работа с клавиатурой, стабильность в React 18 StrictMode) или
   нативный HTML5 drag-and-drop (без новых зависимостей, но хуже UX и доступность). Нужно решение
   архитектора — новая зависимость в web-admin.
2. **Маршрут `/routes/:id`** отсутствует в `router/index.tsx` — либо добавить в М2.7, либо хранить
   выбранный маршрут в query-параметре `?routeId=`.
3. **Оценка времени маршрута.** М2.5 упоминает «пересчёт оценки времени маршрута», но в модели
   `Route` нет поля для неё. Предложение: сервер возвращает `totalEstimatedTimeMin` в ответе
   `GET /api/routes/:id` и в ответе `reorder` — иначе клиент считает Σ сам (как в спецификации).
   Требуется решение Backend Core.
4. **Переупорядочивание `ACTIVE`-маршрута.** Переходы `RouteStatus` определены
   (`shared/types/core.ts` → `ROUTE_ALLOWED_TRANSITIONS`: `DRAFT→{ACTIVE,ARCHIVED}`,
   `ACTIVE→{ARCHIVED,DRAFT}`, `ARCHIVED` терминальный), но не определено, **принудительно ли
   `reorder` переводит `ACTIVE`-маршрут в `DRAFT`**. В спецификации: баннер-предупреждение и явное
   действие «Вернуть в черновик» перед правкой (п. 4.3); требуется решение Backend Core.
5. **Роль SUPERVISOR.** В роутере `/routes` закрыт `RoleGuard roles={['ADMIN']}`; может ли
   бригадир собирать маршруты — не определено (пункт меню «Маршруты» тоже ADMIN-only).
6. **`@@unique([routeId, orderIndex])`** делает массовое обновление порядка чувствительным к
   порядку записи — сервер обязан выполнять `reorder` в транзакции (М2.5 это требует); ошибки
   уникальности нужно маппить в 409 с понятным текстом (описано в п. 6).
7. **Помещения без координат** (`coordsX === null`) не могут быть показаны на плане — в спецификации
   они остаются в списке точек с пометкой; нужно подтвердить, что `reorder` для них допустим.
