# 📋 Экран: Список объектов (`objects_list`)

> DS-003 (М2.8) → реализация в М2.7 (`frontend/web-admin/src/pages/Objects/ObjectList.tsx`).
> Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)), не бинарный макет.
> Данные: `GET /api/objects` (core-service, М2.3).

## 1. Назначение

Точка входа в ядро домена: поиск и отбор объектов обслуживания, переход в карточку объекта,
создание и редактирование объекта. Экран отвечает на вопросы «какие объекты на обслуживании»,
«какой у них статус», «сколько этажей» и служит навигацией к планам этажей и маршрутам.

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL | `/objects` (существует: `router/index.tsx`, `children: [{ path: 'objects' }]`) |
| Пункт меню | «Объекты» (`AdminLayout.NAV`), активен при `/objects` |
| Guard | `AuthGuard` (все авторизованные роли) |
| Чтение | ADMIN, SUPERVISOR, OPERATOR, CLIENT — в текущем роутере ограничений нет |
| Создание/редактирование | ADMIN, SUPERVISOR (предложение; `RoleGuard` на уровне кнопок) |
| Архивирование | ADMIN |

## 4. Состав блоков и элементов

### 4.1. Шапка страницы

| Элемент | Описание |
|---|---|
| Заголовок | «Объекты» — `h1`, `text-2xl font-semibold text-neutral-900` |
| Счётчик | `total` из ответа списка, `text-sm text-neutral-500`, рядом с заголовком |
| Кнопка «Создать объект» | `Button variant="primary" size="md"`, открывает модалку создания (п. 7.1) |

### 4.2. Панель фильтров

| Элемент | Контрол | Поведение |
|---|---|---|
| Поиск | `input type="search"` | debounce 300 мс → query-параметр `search` (по `name`, `address`); placeholder «Название или адрес» |
| Статус | `select` | значения `ACTIVE`, `PAUSED`, `ARCHIVED` (enum `ObjectStatus`) + «Все»; query `status` |
| Тип | `select` | значения — свободная строка `Object.type`; варианты берутся из уже загруженных объектов (distinct) до появления справочника; query `type` |
| Сбросить | `Button variant="ghost" size="sm"` | очищает все фильтры, `skip=0`, видна только при активном фильтре |
| Счётчик активных фильтров | бейдж `bg-primary-50 text-primary-700 rounded-full text-xs px-2 py-0.5` | появляется при ≥1 фильтре |

Все фильтры синхронизируются с query-строкой URL (`useSearchParams`) — состояние экрана
восстанавливается при перезагрузке и доступно по ссылке.

### 4.3. Таблица объектов

| Колонка | Поле API (`Object`) | Формат | Ширина / поведение |
|---|---|---|---|
| Название | `name` | `text-sm font-medium text-neutral-900`, ссылка на `/objects/:id` | `min-w-[220px]`, сортируемая (`sort=name`) |
| Адрес | `address` | `text-sm text-neutral-500`, обрезка по 1 строке + `title` | `min-w-[240px]` |
| Тип | `type` | `text-sm`, бейдж-контур `rounded-md border border-neutral-200 px-2 py-0.5` | 120 px |
| Площадь, м² | `totalArea` | `font-mono text-right`, разделитель разрядов, 1 знак | 120 px, сортируемая |
| Этажей | `floorsCount` | `font-mono text-right` | 90 px |
| Клиент | `clientName` | `text-sm`, вторая строка — `clientContact` (`text-xs text-neutral-400`) | 200 px |
| Статус | `status` | бейдж (п. 4.4) | 130 px |
| Действия | — | иконка `⋮`, dropdown: «Открыть», «Редактировать», далее — только переходы, разрешённые `canTransitionObject` (`shared/types/core.ts`): «Приостановить» (`ACTIVE→PAUSED`), «Возобновить» (`PAUSED→ACTIVE`), «Архивировать» (`ACTIVE/PAUSED→ARCHIVED`); для `ARCHIVED` — дополнительных действий нет (терминальный статус) | 56 px, `sticky right-0` |

- Клик по строке (кроме колонки действий) → `/objects/:id`.
- Сортировка: `name`, `totalArea`, `createdAt`; серверная (`sort`, `order`), индикатор ▲/▼ в шапке.
- Шапка таблицы `sticky top-0 z-10 bg-neutral-50`, чтобы сохранялась при скролле больших списков
  (требование DS-003 «таблицы с большими данными»).
- Плотность строки — 48 px (`h-12`), разделитель `border-b border-neutral-200`.
- Виртуализация не требуется: страница ≤100 строк (`take` ≤ 100), данные грузятся постранично.

### 4.4. Бейдж статуса (`ObjectStatus`)

Подписи берутся из `OBJECT_STATUS_LABELS` (`shared/types/core.ts`) — не дублируются строками в коде.
Единый вид для всех экранов: белая пилюля + цветная точка (мягкая цветная заливка недоступна —
у `success/warning/danger` есть только уровни 500/600, см. README «Пробелы токенов»).

| `status` | Подпись (`OBJECT_STATUS_LABELS`) | Точка | Текст | Разрешённые переходы (`OBJECT_ALLOWED_TRANSITIONS`) |
|---|---|---|---|---|
| `ACTIVE` | Активен | `bg-success-500` | `text-success-600` | `PAUSED`, `ARCHIVED` |
| `PAUSED` | Приостановлен | `bg-warning-500` | `text-warning-600` | `ACTIVE`, `ARCHIVED` |
| `ARCHIVED` | В архиве | `bg-neutral-400` | `text-neutral-500` | — (терминальный) |

Разметка: `inline-flex items-center gap-2 rounded-full border border-neutral-200 bg-white px-2.5 py-0.5 text-xs font-medium`,
точка — `h-1.5 w-1.5 rounded-full`.

## 7. Действия пользователя

| Действие | Триггер | Результат |
|---|---|---|
| Найти объект | ввод в поиск | `search` + `skip=0`, debounce 300 мс |
| Отфильтровать | выбор статуса/типа | `status`/`type` + `skip=0` |
| Сбросить фильтры | «Сбросить» | очистка query-строки |
| Сортировать | клик по шапке колонки | `sort=name|totalArea|createdAt`, `order=asc|desc` |
| Перейти в объект | клик по строке / «Открыть» | навигация на `/objects/:id` |
| Создать объект | «Создать объект» | модалка 7.1 → `POST /api/objects` |
| Редактировать | `⋮` → «Редактировать» | модалка 7.1 в режиме правки → `PATCH /api/objects/:id` |
| Сменить статус | `⋮` → «Приостановить» / «Возобновить» / «Архивировать» | модалка 7.2 (для архива) или сразу → `PATCH /api/objects/:id { status }`; недоступные переходы не показываются (`canTransitionObject`, `shared/types/core.ts`) |
| Сменить страницу | пагинация | `skip = (page-1) * take` |

### 7.1. Модальное окно «Объект» (создание / редактирование)

Поля соответствуют модели `Object` и DTO `create-object.dto` / `update-object.dto`
(`docs/agents/BACKEND_CORE.md`):

| Поле | Тип контрола | Обяз. | Валидация | Поле API |
|---|---|---|---|---|
| Название | `input` | ✔ | 3–120 символов | `name` |
| Адрес | `input` | ✔ | 5–200 символов | `address` |
| Тип | `input` + datalist | ✔ | свободная строка (справочника типов нет) | `type` |
| Широта | `input type="number" step="0.000001"` | ✔ | −90…90, `font-mono` | `lat` |
| Долгота | `input type="number" step="0.000001"` | ✔ | −180…180, `font-mono` | `lng` |
| Общая площадь, м² | `input type="number"` | ✔ | > 0 | `totalArea` |
| Количество этажей | `input type="number"` | ✔ | ≥ 0 (целое) | `floorsCount` |
| Клиент | `input` | ✔ | 2–120 символов | `clientName` |
| Контакт клиента | `input` | ✔ | телефон/email, 5–120 | `clientContact` |
| Статус | `select` | ✔ | `ACTIVE`/`PAUSED`/`ARCHIVED`, по умолчанию `ACTIVE` | `status` |

Кнопки: «Отмена» (`secondary`) / «Создать»/«Сохранить» (`primary`, при запросе — `loading`).
Модалка не закрывается по клику на оверлей, если форма изменена (подтверждение «Отменить изменения?»).

### 7.2. Модальное окно «Архивировать объект»

Заголовок «Архивировать объект?», текст: «Объект „{name}“ перейдёт в статус „В архиве“ и
перестанет попадать в планирование. Этажи, помещения и маршруты сохранятся.»
Кнопки: «Отмена» (`secondary`), «Архивировать» (`danger`).

## 8. Данные из API

### 8.1. Список

`GET /api/objects?skip=&take=&search=&status=&type=&sort=&order=`

| Поле ответа | Тип | Использование |
|---|---|---|
| `items[].id` | string (uuid) | ключ строки, ссылка `/objects/:id` |
| `items[].name` | string | колонка «Название» |
| `items[].address` | string | колонка «Адрес» |
| `items[].type` | string | колонка «Тип», опции фильтра |
| `items[].totalArea` | number | колонка «Площадь, м²» |
| `items[].floorsCount` | number | колонка «Этажей» |
| `items[].clientName`, `items[].clientContact` | string | колонка «Клиент» |
| `items[].status` | `ACTIVE`\|`PAUSED`\|`ARCHIVED` | бейдж статуса |
| `items[].lat`, `items[].lng` | number | в список не выводятся (нужны карточке объекта) |
| `items[].createdAt`, `items[].updatedAt` | ISO 8601 | скрытая сортировка, `title` строки |
| `total` | number | счётчик и пагинация |

### 8.2. Мутации

| Действие | Запрос |
|---|---|
| Создание | `POST /api/objects` (тело — поля из 7.1) |
| Редактирование | `PATCH /api/objects/:id` |
| Архивирование | `PATCH /api/objects/:id { status: "ARCHIVED" }` |

Обновление списка — инвалидация query-ключа `['objects', filters]` (TanStack Query), без перезагрузки страницы.

## 9. Адаптивность (desktop-first)

Диапазоны — из System Design v1 (§2.2): <768 px (phone, `max-md:`), 768–1023 px (tablet,
`md:max-lg:`), ≥1024 px (desktop, `lg:`). Desktop ≥1024 px визуально не меняется.

| Диапазон | Поведение |
|---|---|
| ≥1024 px (desktop) | как сейчас: таблица 8 колонок, сайдбар `w-60` |
| 768–1023 px (tablet) | таблица остаётся таблицей (внутренний скролл `overflow-x-auto`), не карточки; сайдбар — иконочная рейка `w-16` (64 px), доработка `AdminLayout` в М2.7 |
| <768 px (phone) | таблица → карточки через `ResponsiveTable` (название, адрес, бейдж статуса, площадь/этажи в `font-mono`, действия); фильтры `min-w-[240px] flex-1` → `max-md:w-full`, поиск на всю ширину; навигация — бургер/drawer + нижняя навигация (5 слотов: Заявки, Дашборд, Объекты, Сообщения + «Ещё»); модалки fullscreen (ConfirmDialog — bottom sheet) |

## 10. Открытые вопросы

1. **Перечисление `Object.type`** в схеме не определено (`type` — свободная строка, справочника
   типов нет). Фильтр «Тип» строится по distinct-значениям; нужен справочник либо явное решение,
   что тип остаётся свободным текстом.
2. **Объём UI по статусам.** Статусы и переходы определены (`shared/types/core.ts`:
   `OBJECT_STATUS_LABELS`, `OBJECT_ALLOWED_TRANSITIONS`, `ARCHIVED` терминальный). Открыто:
   выводить ли в М2.7 «Приостановить»/«Возобновить» или ограничиться архивированием и
   редактированием.
3. **Жёсткое удаление объекта** (`DELETE /api/objects/:id`) в спецификации не используется: выбран
   безопасный путь `status=ARCHIVED`. Нужно решение архитектора о наличии удаления без архива
   (и о каскаде `Floor`/`Room`/`Route` при нём — в схеме `onDelete: Cascade`).
4. **`floorsCount` — хранимое поле, дублирующее связь `floors`.** Риск расхождения с фактическим
   числом этажей. Предложение: выводить в колонке фактическое количество (`floors.length`) либо
   пересчитывать `floorsCount` на бэкенде при CRUD этажей.
5. **Endpoint списка с фильтрами/сортировкой** в `ПЛАН.md` М2.3 задан как «фильтры по статусу/типу»;
   параметры `search`, `sort`, `order` — предложение (соглашение `skip`/`take` и `{ items, total }`
   взято из уже реализованных `auth-service`/`file-service`). Уточнить в Swagger core-service в М2.7.
6. **Роли на запись.** В `router/index.tsx` для `/objects` нет `RoleGuard`; кто может создавать и
   редактировать объекты (ADMIN/SUPERVISOR?) — требуется решение.
7. **Мягкая заливка бейджей** невозможна без токенов `*-50` (см. README, п. 1 пробелов).
