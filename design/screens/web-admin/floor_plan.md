# 🗺 Экран: План этажа и редактор помещений (`floor_plan`)

> DS-003 (М2.8) → реализация в М2.7 (`frontend/web-admin/src/pages/Floors/FloorPlan.tsx` +
> `RoomEditor.tsx`). Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)).
> Данные: `GET /api/floors/:id`, `POST /api/floors/:id/plan` (М2.3), `rooms` CRUD (М2.4),
> `GET /api/tech-cards` (М2.6).

## 1. Назначение

Просмотр изображения плана этажа и экспликация помещений **прямо по плану**: клик/протяжка мышью
по изображению создаёт помещение с координатами, клик по помещению открывает его карточку.
Экран — источник геометрии для маршрутов ([`route_builder.md`](./route_builder.md)) и точка
привязки техкарт к помещениям.

Требование М2.7: «Floors (просмотр плана-изображения, загрузка плана, редактор помещений с кликом
по координатам)». Требование DS-003: desktop-first, модальные окна/drawers.

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL | `/objects/:id/floors/:floorId` — **предложено**; в `router/index.tsx` маршрут отсутствует |
| Требуемое дополнение роутера (М2.7) | `{ path: 'objects/:id/floors/:floorId', element: <RoleGuard roles={['ADMIN','SUPERVISOR']}><FloorPlanPage /></RoleGuard> }` |
| Пункт меню | нет прямого пункта; навигация — из карточки объекта ([`object_detail.md`](./object_detail.md)) |
| Guard | `AuthGuard` + `RoleGuard roles={['ADMIN','SUPERVISOR']}` для редактирования; чтение — все авторизованные (предложение) |
| Возврат | крошки «Объекты / {object.name} / {floor.name}» |

## 4. Состав блоков и элементов

### 4.1. Toolbar

| Элемент | Контрол | Поведение |
|---|---|---|
| Крошки | текст | «Объекты / {object.name} / {floor.name}», `text-sm text-neutral-500` |
| Режим | сегментированный переключатель | «Просмотр» / «Добавить помещение» (`RoomEditor`); в режиме добавления курсор `crosshair` |
| «Масштаб, м/пкс» | `input type="number" step="0.001"` + кнопка «Сохранить» | значение `Floor.planScale`; доступно только ADMIN/SUPERVISOR; подсказка «1 px ≈ {planScale} м» |
| Зум | `[−] [100 %] [+]` и «Вписать» | пределы 25–400 %, шаг 25 %; «Вписать» — `object-contain` в область canvas |
| «Заменить план» | `Button variant="secondary" size="sm"` | модалка 7.1 (`POST /api/floors/:id/plan`) |
| «Экспорт CSV» | `Button variant="ghost" size="sm"` | клиентский экспорт экспликации (P2, `text/csv`, UTF-8 BOM) |

### 4.2. Левая панель «Экспликация»

| Элемент | Описание |
|---|---|
| Счётчик | «12 помещений, 348,5 м²» — Σ `Room.areaM2`, `font-mono` для числа |
| Поиск | `input`, фильтр по `name` (клиентский, мгновенный) |
| Фильтр «Зона» | `select` по distinct-значениям `Room.zone` |
| Фильтр «Тип» | `select` по distinct-значениям `Room.floorType` |
| Строка помещения | `N · {name}` (`text-sm font-medium`), вторая строка — `{areaM2} м² · {zone}` (`text-xs text-neutral-500`), бейдж техкарты (см. 4.5), hover `bg-neutral-50`, выбранная — `bg-primary-50 border-l-2 border-primary-600` |
| Сортировка | «по порядку добавления» / «по площади» / «по названию» (клиентская) |
| Итого | Σ `areaM2` + расхождение с `Object.totalArea` (P2, справочно) |

Выбор в списке подсвечивает помещение на плане (рамка `border-primary-600`) и открывает Drawer (7.3).
Наведение на строку списка — hover-подсветка соответствующего прямоугольника (`bg-primary-100`).

### 4.3. Canvas плана

| Элемент | Описание |
|---|---|
| Изображение | `<img src={floor.planImageUrl}>`, `max-w-none`, начало координат — левый верхний угол изображения; область прокрутки `overflow-auto` |
| Масштабирование | CSS `transform: scale(z)` от левого верхнего угла; размеры контейнера пересчитываются, чтобы не появлялись пустые поля |
| Панорамирование | drag средней кнопкой мыши или `Space` + drag; скролл колёсиком; `Ctrl` + колёсико — зум к курсору |
| Фон вокруг плана | `--color-neutral-100` | `bg-neutral-100` |
| Рамка плана | `border border-neutral-200 rounded-md shadow-sm` |
| Сетка (опция) | шаг 50 px, линии `rgba` нейтрального цвета; включается тумблером «Сетка» (P2) |
| Подсказка режима | нижняя плашка `bg-neutral-900 text-neutral-100 text-xs rounded-md px-3 py-1`: «Протяните рамку, чтобы создать помещение» |
| Маркер помещения | прямоугольник, позиция и размер — `Room.coordsX`, `coordsY`, `coordsWidth`, `coordsHeight` (в пикселях изображения) |
| Подпись помещения | `{orderInRoute?} {name}` — `text-xs font-medium`, по центру сверху; скрывается при `z < 50 %` |
| Состояния прямоугольника | обычное — `bg-primary-50 border border-primary-500`; hover — `bg-primary-100`; выбранное — `bg-primary-200 border-2 border-primary-600`; без техкарты — `border-dashed border-warning-500 bg-primary-50` |
| Рисование нового | в режиме «Добавить помещение» протяжка рисует рамку-превью `border-2 border-dashed border-primary-600 bg-primary-50`; по отпускании — модалка 7.2 |

> **Почему `primary-50/100/200`, а не полупрозрачный `primary-500`:** у цветов, заданных в
> Tailwind как `var(--color-…)`, модификатор прозрачности (`bg-primary-500/15`) не даёт надёжного
> результата; полупрозрачные слои собираются из реальных токенов `--color-primary-50/100/200`
> (см. README, пробел 2).

### 4.4. Drawer «Помещение»

Открывается справа (`fixed right-0 top-16 h-[calc(100vh-4rem)] w-96 bg-white border-l border-neutral-200 shadow-lg` —
`--shadow-lg`), закрывается по `Esc`, `×` или клику вне drawer.

| Поле | Контрол | Обяз. | Валидация | Поле API (`Room`) |
|---|---|---|---|---|
| Название | `input` | ✔ | 1–80 символов | `name` |
| Площадь, м² | `input type="number" step="0.1"` | ✔ | > 0 (М2.4) | `areaM2` |
| Тип помещения | `input` + datalist | ✔ | свободная строка (справочника нет) | `floorType` |
| Зона | `input` | ✖ | свободная строка (`zone-a`, `zone-b`…) | `zone` |
| Техкарта | `select` | ✖ | значение из `GET /api/tech-cards`; «не выбрана» = `null` | `techCardId` |
| Координаты | 4 × `input type="number"` (`X`, `Y`, `Ш`, `В`) | ✖ | целые ≥ 0, прямоугольник внутри размеров плана (`width`/`height` изображения) | `coordsX`, `coordsY`, `coordsWidth`, `coordsHeight` |
| Подсказка площади | текст | — | `coords` × `planScale²` — «по геометрии ≈ 24,3 м²» (расчёт только как подсказка) | — |
| Метаданные | текст | — | `id` и `createdAt`/`updatedAt` — `font-mono text-xs text-neutral-400` | `id`, `createdAt`, `updatedAt` |

Кнопки: «Удалить помещение» (`danger`, подтверждение 7.4), «Отмена», «Сохранить» (`primary`).

### 4.5. Бейдж техкарты

| Условие | Вид |
|---|---|

| `techCardId === null` | пилюля `bg-white text-warning-600 border border-warning-500 text-xs`: «Техкарта не выбрана» |

## 6. Состояния экрана

| Состояние | Триггер | Отображение |
|---|---|---|
| Загрузка этажа и помещений | `isLoading` | скелетон левой панели (5 строк) + серый блок canvas с `Spinner` по центру |
| План не загружен | `planImageUrl === null` | центр canvas — dashed-карточка `rounded-xl border border-dashed border-neutral-300 bg-white p-10 text-center`: «План этажа не загружен», пояснение «Загрузите PNG, JPG, SVG или PDF ≤ 10 МБ», `Button variant="primary"` «Загрузить план»; рисование помещений недоступно (кнопка «Добавить помещение» — `disabled` с `title`-подсказкой) |
| Изображение грузится | `img.onload` не сработал | контейнер с фиксированным `aspect-ratio` (по `width`/`height` из метаданных файла) и `animate-pulse bg-neutral-200` |
| Ошибка изображения | `img.onerror` (URL недоступен, MinIO недоступен) | баннер `border-danger-500 text-danger-600` над canvas: «Не удалось открыть изображение плана» + «Повторить»; координаты помещений не редактируются |
| Нет помещений | `rooms.length === 0` | левая панель: текст «Помещений пока нет» (`text-sm text-neutral-400`) + `Button variant="primary" size="sm"` «Добавить помещение»; на плане — плашка-подсказка |
| Фильтры/поиск без результата | список пуст, фильтры активны | «Ничего не найдено» + «Сбросить фильтры» |
| Ошибка сохранения помещения | 400 (площадь ≤ 0, координаты вне плана) | поля с ошибкой `border-danger-500`, текст `text-xs text-danger-600`: «Площадь должна быть больше 0», «Прямоугольник выходит за границы плана»; drawer не закрывается |
| Конфликт при удалении | 409 (помещение используется в маршруте) | диалог: «Помещение входит в маршрут(ы): {names}. Удалить вместе с точками?» |
| План — PDF | `planImageUrl` ведёт на `application/pdf` | canvas показывает заглушку: «PDF-план нельзя редактировать в браузере» + `Button variant="secondary"` «Открыть PDF в новой вкладке»; редактор помещений доступен только числовыми полями (без рисования) — требуется решение (п. 10) |
| Нет прав на запись | роль OPERATOR/CLIENT | toolbar без «Заменить план»/«Сохранить масштаб», рисование и drawer — read-only |

| Переместить/растянуть помещение | drag тела / за угловые маркеры (по 8 px, появляются при выборе) | локальное изменение `coords*` → «Сохранить» в Drawer (`PATCH`) |
| Удалить помещение | Drawer → «Удалить помещение» | подтверждение 7.4 → `DELETE /api/rooms/:id` |

| Перейти к маршрутам этажа | `+ Помещение ▾` → «Собрать маршрут» (P2) | `/routes?floorId=…` |

### 7.1. Модальное окно «Загрузка/замена плана»

Полностью повторяет [`object_detail.md`](./object_detail.md) п. 7.3 (`POST /api/floors/:id/plan`,
multipart `file` + `scale`, форматы PNG/JPG/PDF/SVG, ≤ 10 МБ). При замене плана с уже нарисованными
помещениями — предупреждение `text-warning-600`: «Координаты {n} помещений могут перестать
соответствовать новому изображению».

### 7.2. Модальное окно «Новое помещение»

Поля — как в Drawer 4.4, но в компактной форме; координаты предзаполнены из нарисованной рамки
(`coordsX`, `coordsY`, `coordsWidth`, `coordsHeight` — целые пиксели изображения).
Обяз. поля: `name`, `areaM2`, `floorType`. Кнопки: «Отмена» / «Создать».

### 7.3. Drawer «Помещение»

См. 4.4. Является основной формой правки (используется вместо модалки, чтобы план оставался видимым).

### 7.4. Подтверждение удаления

Мини-диалог (не более 2 строк): «Удалить помещение „{name}“?» + предупреждение, если помещение
входит в маршруты (`RoutePoint`), с перечислением названий маршрутов. Кнопки «Отмена» / «Удалить» (`danger`).

## 8. Данные из API

### 8.1. Этаж

`GET /api/floors/:id` → `Floor`.

| Поле | Тип | Использование |
|---|---|---|
| `id` | uuid | ключ, запросы помещений/маршрутов |
| `objectId` | uuid | крошки (название объекта) |
| `number` | number | крошки/заголовок («1 этаж») |
| `name` | string | крошки/заголовок |
| `planImageUrl` | string \| null | изображение плана; `null` → состояние «План не загружен» |
| `planScale` | number \| null | поле «Масштаб, м/пкс», подсказка площади |
| `rooms[]` | `Room[]` | экспликация и прямоугольники на плане |
| `routes[]` | `Route[]` | ссылка «Маршруты этажа», предупреждение при удалении помещения |
| `createdAt`, `updatedAt` | ISO 8601 | метаданные |

### 8.2. Помещение

`GET /api/rooms?floorId=:id` → `{ items: Room[], total }` (соглашение `skip`/`take`).

| Поле | Тип | Использование |
|---|---|---|
| `id` | uuid | ключ, запросы |
| `floorId` | uuid | привязка при создании |
| `name` | string | подпись на плане, список |
| `areaM2` | number | список, Σ площади, валидация > 0 |
| `floorType` | string | поле «Тип помещения», фильтр |
| `zone` | string \| null | фильтр «Зона», вторая строка списка |
| `coordsX`, `coordsY` | number \| null | позиция прямоугольника на плане, px |
| `coordsWidth`, `coordsHeight` | number \| null | размеры прямоугольника, px |
| `techCardId` | string \| null | select техкарты, бейдж 4.5 |
| `createdAt`, `updatedAt` | ISO 8601 | метаданные в drawer |

### 8.3. Мутации

| Действие | Запрос |
|---|---|
| Создание помещения | `POST /api/rooms { floorId, name, areaM2, floorType, zone?, techCardId?, coordsX, coordsY, coordsWidth, coordsHeight }` |
| Изменение | `PATCH /api/rooms/:id` |
| Удаление | `DELETE /api/rooms/:id` |
| Загрузка плана | `POST /api/floors/:id/plan` (multipart: `file`, `scale`) |
| Масштаб | `PATCH /api/floors/:id { planScale }` |
| Техкарты для select | `GET /api/tech-cards?skip=0&take=100` |
| Размеры изображения | `GET /api/files/:id` (поля `width`, `height`) или `img.naturalWidth/naturalHeight` после загрузки |

**Валидация координат (М2.4):** «координаты внутри размера плана» — сравнение идёт с `width`/`height`
изображения; для растровых планов источник истины — `naturalWidth`/`naturalHeight` загруженного
изображения (или метаданные file-service), для PDF/SVG размеры могут отсутствовать (см. п. 10).

## 9. Адаптивность (desktop-first)

|---|---|

## 10. Открытые вопросы

1. **Маршрут `/objects/:id/floors/:floorId`** отсутствует в `router/index.tsx` — добавить в М2.7
   (см. п. 2). Также в `AdminLayout.NAV` нет пункта «Этажи» — навигация только из карточки объекта.
2. **PDF-планы.** М2.3 разрешает PNG/JPG/PDF/SVG, но координатная привязка помещений возможна
   только для растрового изображения. Требуется решение: (а) конвертировать PDF→PNG на бэкенде в
   file-service, (б) запретить PDF для планов, (в) ограничиться режимом «только числовые координаты».
   Спецификация предполагает (а) как целевое и (в) как dev-fallback.
3. **SVG-планы.** `img.naturalWidth` для SVG может быть 0/не задан (нет `width`/`height` в корне) —
   нужна нормализация масштаба (`viewBox`) либо принудительное требование размеров.
4. **`planScale` — «сколько метров в одном пикселе»** (комментарий в `schema.prisma`). Не определено,
   `areaM2` вводится руками или считается из `coords × planScale²`. В спецификации — ручной ввод +
   подсказка; нужно решение архитектора (М2.4 задаёт только «площадь > 0»).
5. **Свободные строки `floorType` и `zone`** — справочников в схеме нет; фильтры строятся по
   distinct-значениям загруженных помещений. Нужен ли справочник типов помещений — вопрос к бэкенду.
6. **DnD-перемещение/ресайз помещений на плане** требует библиотеки перетаскивания или ручной
   обработки `pointermove` (см. [`route_builder.md`](./route_builder.md) п. 10.1 — решение о зависимости).
7. **`GET /api/files/:id` требует токена**, а `<img src>` его не передаёт. Варианты: presigned-URL
   от core-service, публичное чтение bucket `plans` (уже настроено в file-service, М2.1) либо
   blob-загрузка через `api/client.ts` с `Authorization`. Спецификация предполагает публичное
   чтение bucket `plans` (как в М2.1); нужно подтверждение.
