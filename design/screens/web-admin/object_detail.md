# 🏢 Экран: Карточка объекта (`object_detail`)

> DS-003 (М2.8) → реализация в М2.7 (`frontend/web-admin/src/pages/Objects/ObjectDetail.tsx`,
> форма — `ObjectForm.tsx`). Тип артефакта — текстовая спецификация (см. [`README.md`](./README.md)).
> Данные: `GET /api/objects/:id`, `GET /api/floors?objectId=`, `POST /api/floors`,
> `POST /api/floors/:id/plan` (М2.3).

## 1. Назначение

Паспорт объекта: реквизиты, клиент, координаты, статус; управление этажами (создание,
переименование, удаление, загрузка плана этажа); навигация к плану этажа и к маршрутам объекта.
Это «хаб», из которого администратор спускается на уровень этажа → помещений → маршрутов.

## 2. Маршрут и доступ

| Параметр | Значение |
|---|---|
| URL | `/objects/:id` (существует: `router/index.tsx`, `children: [{ path: 'objects/:id' }]`) |
| Возврат | хлебные крошки «Объекты / {name}» → `/objects` |
| Guard | `AuthGuard`; запись — ADMIN, SUPERVISOR (предложение) |
| Связь с другими экранами | «Открыть план этажа» → `/objects/:id/floors/:floorId` ([`floor_plan.md`](./floor_plan.md)); «Маршруты этажа» → `/routes?floorId=…` ([`route_builder.md`](./route_builder.md)) |

## 4. Состав блоков и элементов

### 4.1. Шапка страницы

| Элемент | Описание |
|---|---|
| Крошки | «Объекты / {name}», `text-sm text-neutral-500`, ссылка на `/objects` |
| Заголовок | `h1` `text-2xl font-semibold text-neutral-900` — `name` |
| Бейдж статуса | как в [`objects_list.md`](./objects_list.md) п. 4.4 (`ACTIVE`/`PAUSED`/`ARCHIVED`) |
| «Редактировать» | `Button variant="secondary"` → модалка 7.1 |
| «Добавить этаж» | `Button variant="primary"` → модалка 7.2 |
| «В архив» | `Button variant="danger"` — только при `canTransitionObject(status, 'ARCHIVED')` (`ACTIVE`/`PAUSED`; `ARCHIVED` терминальный), подтверждение 7.4 |

### 4.2. Паспорт объекта (definition grid)

Двухколоночная сетка (`grid grid-cols-2 gap-x-8 gap-y-4`), подпись — `text-xs text-neutral-500`,
значение — `text-sm text-neutral-900`; числа и координаты — `font-mono`.

| Поле | Поле API (`Object`) | Формат |
|---|---|---|
| Тип | `type` | текст |
| Общая площадь | `totalArea` | `font-mono`, 1 знак, «м²» |
| Этажей (заявлено) | `floorsCount` | целое |
| Этажей (фактически) | длина `floors` | целое; при расхождении — пометка `text-warning-600` со знаком ⚠ |
| Адрес | `address` | текст, перенос по 2 строкам |
| Клиент | `clientName` | текст |
| Контакт клиента | `clientContact` | ссылка `tel:`/`mailto:`, если распознан |
| Координаты | `lat`, `lng` | `font-mono`, 6 знаков; ссылка «Открыть в картах» (внешняя, только если задан Mapbox-токен) |
| Создан / изменён | `createdAt`, `updatedAt` | `dd.MM.yyyy HH:mm`, `text-xs text-neutral-500` |
| Площадь помещений (справочно) | Σ `Room.areaM2` | собирается из таба «Сводка помещений»; при отсутствии данных — «—» |

### 4.3. Табы

| Таб | Приоритет | Содержимое |
|---|---|---|
| «Этажи» | P0 (М2.7) | таблица этажей (п. 4.4) |
| «Сводка помещений» | P2 | плоский список всех помещений объекта (`name`, `areaM2`, `floorType`, `zone`, `techCardId`), Σ площади; требует фильтра `GET /api/rooms?objectId=` (в спецификации API не заявлен — открытый вопрос) |
| «Маршруты объекта» | P2 | маршруты всех этажей (`name`, `status`, число точек, Σ `estimatedTimeMin`), ссылки в [`route_builder.md`](./route_builder.md); реализуется клиентской агрегацией по этажам |

### 4.4. Таблица этажей

| Колонка | Поле API (`Floor`) | Формат |
|---|---|---|
| № | `number` | `font-mono`, сортировка по возрастанию |
| Название | `name` | `text-sm font-medium`, ссылка на план этажа |
| План | `planImageUrl` | превью 64×40 (`object-cover rounded-md border border-neutral-200`) или кнопка «Загрузить план» (`Button variant="ghost" size="sm"`), если `planImageUrl === null` |
| Масштаб | `planScale` | `font-mono`, «{planScale} м/пкс» или «—» |
| Помещений | длина `rooms` | `font-mono`; `0` — `text-neutral-400` |
| Маршрутов | длина `routes` | `font-mono` |
| Действия | — | `⋮`: «Открыть план», «Загрузить/Заменить план», «Редактировать», «Удалить» |

- Клик по строке → `/objects/:id/floors/:floorId`.
- Сортировка по `number` на клиенте (этажи одного объекта — короткий список); пагинация не нужна.
- Альтернативная раскладка (1280–1439 px): карточки этажей в сетке `grid grid-cols-2 gap-4` —
  превью плана, номер и название, счётчики помещений/маршрутов, те же действия.

## 6. Состояния экрана

| Состояние | Триггер | Отображение |
|---|---|---|
| Загрузка | `isLoading` объекта | скелетон паспорта (6 строк `animate-pulse bg-neutral-200 h-4 rounded-md`) + скелетон таблицы этажей |
| Объект не найден | 404 | dashed-карточка: «Объект не найден или удалён», `Button variant="secondary"` «К списку объектов» |
| Ошибка загрузки | 5xx/сеть | баннер `border-danger-500 text-danger-600` + «Повторить» |
| Нет этажей | `floors.length === 0` | dashed-карточка внутри таба: «У объекта ещё нет этажей» + `Button variant="primary"` «Добавить этаж» |
| Нет плана этажа | `planImageUrl === null` | в колонке «План» — `Button variant="ghost" size="sm"` «Загрузить план»; в строке — пометка «План не загружен» (`text-xs text-warning-600`) |
| Загрузка плана в процессе | upload | прогресс: `Spinner` (`components/ui/Button.tsx`) + текст «Загрузка плана…», строка `opacity-60` |
| Объект в архиве | `status === 'ARCHIVED'` | баннер `bg-neutral-100 text-neutral-600`: «Объект в архиве. Редактирование ограничено.»; кнопки создания этажа/маршрутов — `disabled` |
| Частичный сбой (объект загружен, этажи нет) | ошибка только `floors` | паспорт отрисован, в табе — баннер ошибки с «Повторить» |

## 7. Действия пользователя

| Действие | Триггер | Результат |
|---|---|---|
| Редактировать объект | «Редактировать» | модалка 7.1 → `PATCH /api/objects/:id` |
| Архивировать объект | «В архив» | подтверждение 7.4 → `PATCH /api/objects/:id { status: "ARCHIVED" }` (переход разрешён из `ACTIVE`/`PAUSED`) |
| Добавить этаж | «Добавить этаж» | модалка 7.2 → `POST /api/floors { objectId, number, name }` |
| Редактировать этаж | `⋮` → «Редактировать» | модалка 7.2 в режиме правки → `PATCH /api/floors/:id` |
| Загрузить/заменить план | `⋮` или кнопка в колонке «План» | модалка 7.3 → `POST /api/floors/:id/plan` (multipart) |
| Открыть план этажа | клик по строке / `⋮` → «Открыть план» | `/objects/:id/floors/:floorId` |
| Удалить этаж | `⋮` → «Удалить» | подтверждение 7.5 → `DELETE /api/floors/:id` |
| Перейти к маршрутам | таб «Маршруты объекта» → маршрут | `/routes?floorId=…` |

### 7.1. Модальное окно «Объект»

Полностью повторяет форму из [`objects_list.md`](./objects_list.md) п. 7.1 (11 полей модели
`Object`, `PATCH` вместо `POST`). Кнопка — «Сохранить».

### 7.2. Модальное окно «Этаж» (создание / редактирование)

| Поле | Контрол | Обяз. | Валидация | Поле API (`Floor`) |
|---|---|---|---|---|
| Номер этажа | `input type="number" min="1"` | ✔ | целое ≥ 1; уникален в объекте (`@@unique([objectId, number])` → 409 «Этаж с таким номером уже есть») | `number` |
| Название | `input` | ✔ | 1–60 символов, по умолчанию «{number} этаж» | `name` |
| Масштаб плана, м/пкс | `input type="number" step="0.001"` | ✖ | > 0; доступно и при создании, обычно задаётся вместе с планом | `planScale` |

Кнопки: «Отмена» / «Создать»/«Сохранить».

### 7.3. Модальное окно «Загрузка плана этажа»

| Элемент | Описание |
|---|---|
| Зона файла | drag-and-drop `rounded-xl border-2 border-dashed border-neutral-300 bg-neutral-50 p-8 text-center` + «Выберите файл»; форматы **PNG, JPG, PDF, SVG** (М2.3 / `BACKEND_CORE.md` п. 3), ≤ 10 МБ |
| Имя файла | после выбора — `text-sm text-neutral-800` + размер `text-xs text-neutral-500` |
| Превью | после выбора — превью изображения (`max-h-48 rounded-md border border-neutral-200`); для SVG/PDF превью может отсутствовать (пометка «Предпросмотр недоступен») |
| Масштаб, м/пкс | `input type="number" step="0.001"`, обяз. при загрузке; подсказка «1 px ≈ {scale} м» |
| Требование к разрешению | для планов **не** применяется (лимит ≥1280×720 — только для `kind=photo` в file-service) |
| Прогресс | `<progress>`/полоса `bg-primary-500` + `Spinner`, отмена недоступна (запрос короткий) |

Кнопки: «Отмена» / «Загрузить» (`loading`). Ошибки: 400 «Недопустимый формат», 413 «Файл больше 10 МБ».

### 7.4. Модальное окно «Архивировать объект?»

Текст: «Объект „{name}“ перейдёт в статус „В архиве“. Этажи, помещения и маршруты сохранятся.»
Кнопки: «Отмена» / «Архивировать» (`danger`).

### 7.5. Модальное окно «Удалить этаж?»

Текст: «Этаж „{name}“ будет удалён вместе с помещениями ({roomsCount}) и маршрутами ({routesCount}).
Действие необратимо.» (в схеме `onDelete: Cascade` для `Room` и `Route` от `Floor`).
Кнопка «Удалить» (`danger`) активна только после ввода названия этажа при `roomsCount > 0`.

## 8. Данные из API

### 8.1. Объект

`GET /api/objects/:id` → `Object` + вложенные `floors`.

| Поле | Тип | Использование |
|---|---|---|
| `id` | uuid | маршруты вложенных экранов |
| `name`, `address`, `type` | string | паспорт |
| `lat`, `lng` | number | паспорт (координаты) |
| `totalArea` | number | паспорт |
| `floorsCount` | number | паспорт (сверить с длиной `floors`) |
| `clientName`, `clientContact` | string | паспорт |
| `status` | `ACTIVE`\|`PAUSED`\|`ARCHIVED` | бейдж, режим read-only |
| `createdAt`, `updatedAt` | ISO 8601 | паспорт |
| `floors[].id`, `.number`, `.name`, `.planImageUrl`, `.planScale`, `.rooms`, `.routes` | — | таблица этажей |

### 8.2. Этажи и план

| Действие | Запрос |
|---|---|
| Список этажей объекта | `GET /api/floors?objectId=:id` (при отсутствии include — отдельный запрос) |
| Создание | `POST /api/floors { objectId, number, name, planScale? }` |
| Изменение | `PATCH /api/floors/:id { number?, name?, planScale? }` |
| Удаление | `DELETE /api/floors/:id` |
| Загрузка плана | `POST /api/floors/:id/plan` — `multipart/form-data`: `file` (PNG/JPG/PDF/SVG) + `scale`; в ответе этаж с заполненными `planImageUrl` и `planScale` |

Правило отображения плана: `planImageUrl` — URL объекта в MinIO (bucket `plans`) либо URL
file-service; для изображений используется `GET /api/files/:id`-метаданные (`width`, `height`)
при расчёте координат помещений на экране [`floor_plan.md`](./floor_plan.md).

## 9. Адаптивность (desktop-first)

| Диапазон | Поведение |

## 10. Открытые вопросы

1. **Маршрут плана этажа.** `/objects/:id/floors/:floorId` в `router/index.tsx` отсутствует —
   требуется добавить в М2.7 (см. [`floor_plan.md`](./floor_plan.md) п. 2).
2. **Фильтры `GET /api/rooms?objectId=` и `GET /api/routes?objectId=`** не заявлены в
   `API_SPECIFICATION.md` (§3: `rooms` — экспликация, `routes` — CRUD). Табы «Сводка помещений»
   и «Маршруты объекта» — P2: либо добавить фильтры на бэкенде, либо агрегировать на клиенте
   обходом этажей.
3. **Права на загрузку плана и удаление этажа** не заданы (`RoleGuard` для `/objects/*` в роутере
   отсутствует). Предложение: ADMIN/SUPERVISOR.
4. **Ссылка «Открыть в картах»** зависит от Mapbox-токена (риск R3 в `ПЛАН.md`); до получения
   токена — без ссылки.
5. **`floorsCount` vs фактическое число этажей** — требуется правило пересчёта на бэкенде
   (см. [`objects_list.md`](./objects_list.md) п. 10.2).
6. **Поведение PDF/SVG-плана** в модалке (превью) и на экране плана — требуется решение
   (см. [`floor_plan.md`](./floor_plan.md) п. 10).
