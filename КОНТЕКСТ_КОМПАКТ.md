## 1. Что за проект

**CLEANFINE** — управление клинингом: 9 микросервисов NestJS, React (админ + портал), Flutter (оператор), PostgreSQL+PostGIS, Redis, RabbitMQ, MinIO. Монорепо pnpm.

| Клиент | Путь | Роль |
|---|---|---|
| Web Admin | `frontend/web-admin` | операции, RBAC, адаптив &lt;768 |
| Web Client | `frontend/web-client` | портал заказчика (`ownerClientId`) |
| Mobile | `mobile/cleaning-ops-app` | offline-first, SOS, GPS, чек-листы; вкладка «Админ» (доска действий) для ADMIN/SUPERVISOR |
| Desktop macOS | `mobile/cleaning-ops-app/macos` | тот же Flutter-код, `CLEANFINE.app` в `/Applications` (ярлык на столе) |
| Desktop Windows | `mobile/cleaning-ops-app/windows` | собирается только в GitHub Actions (`windows-build.yml`, раннер windows-latest) — на Mac нельзя |

**Сервисы :3001–:3009:** auth, files, core, gps, tickets, notifications, materials, schedule, chat — у каждого своя БД `cleaning_ops_*` + Prisma.

## 4. Ловушки (читать перед правками)

1. **`SERVICE_AUTH_PASSWORD` = `admin123`** — иначе 503 на создании объекта (`ownerClientId`).
2. **`RABBITMQ_URL` пароль ≠ `DB_PASSWORD`** — брать из `RABBITMQ_PASSWORD`.
3. **`MINIO_SECRET_KEY` = root password**, не user.
4. **shared:** перед `node dist/main.js` нужна копия в `node_modules/@cleaning-ops/shared` (см. Dockerfile) / `pnpm build:shared` перед сборкой.
5. **pnpm 8 + Node 24+** → `ERR_INVALID_THIS`: ставить `pnpm@10` и `npm_config_manage_package_manager_versions=false`.
6. **Prisma per-service:** `output = "../node_modules/.prisma/client"`; генератор: `node scripts/ci/prisma-clients.mjs`.
7. **Schedule-таблицы** без `@@map` → `"ScheduleEvent"`, не `schedule_events`.
8. **NetworkPolicy в k8s** не включать без allow для traefik (иначе 502).
9. **minio image:** `bitnamilegacy/minio` (quay/dockerhub minio недоступны).
10. **reg108** — виртуальный хостинг, **sudo запрещён**; nginx правится панелью reg.ru.
11. **Не коммитить** `.env`, k8s-секреты, `/root/cleanfine-migrate/secrets.env`.
12. **traefik 3.7:** аннотации middleware у plain Ingress **молча игнорируются** — редиректы/база-auth делать через **IngressRoute** (см. `infra/k8s/ingress.yaml`).
13. **vps2:** helm требует `~/.kube/config` → симлинк на `/etc/rancher/k3s/k3s.yaml`; Alertmanager `retention` только h/m/s.
14. **macOS Keychain:** ad-hoc сборка без AppIdentifierPrefix → `-34018 errSecMissingEntitlement` в Data Protection keychain. Лечение: `MacOsOptions(usesDataProtectionKeychain: false)` (secure_storage v11), App Sandbox снят (`Release.entitlements` — только `network.client`).
15. **`API_HOST` по умолчанию `10.0.2.2`** (Android-эмулятор) — для iOS/macOS обязательно передавать `--dart-define` (`API_HOST=localhost` или полные `API_*_URL`), иначе клиент «висит» без сети. В `CLEANFINE.app` вшиты `AUTO_LOGIN_EMAIL/PASSWORD=admin/admin123` — пересобрать без них перед передачей наружу.
16. **Две копии репо на машине:** `~/Desktop/CLOUDE/Clean` (эта сессия) и `~/Desktop/MIMO/Clean` (другой агент, там собирались macOS-сборка и PDF-руководство). Коммиты синхронны через `origin/develop`; неотслеживаемые файлы (`output/`, PDF, `generated-*.png`) — локальные, не коммитить.
17. **Данные пользователя в Riverpod** — каждый новый провайдер с данными пользователя обязан `ref.watch(sessionScopeProvider)`, иначе переживёт выход/вход другого. Riverpod 2 при пересборке несёт прежнее значение в `AsyncLoading/AsyncError` → `valueOrNull` может показать данные прошлого пользователя: в UI опираться на `when`, а `valueOrNull` фильтровать (`isReloading || hasError`, см. `home_today_page.dart`).
18. **`POST /api/auth/refresh` отвечает 201** (у Nest нет `@HttpCode`) — клиенты должны принимать 200/201. **`POST /api/auth/logout` без `refreshToken` отзывает ВСЕ сессии пользователя** (в т.ч. чужие клиенты стенда): при ручных проверках curl-ом всегда передавать `refreshToken`.

## 5. Полезные команды

```bash
# локальный стенд
docker compose --env-file .env -f infra/docker/docker-compose.yml up -d
pnpm build:shared && pnpm -r --if-present build
# shared → node_modules для node dist/main.js (см. §4.4)

# лончеры с автологином (копии на рабочем столе, источники в scripts/launchers/):
#   Cleaning-Ops-Admin.command    → :5175 admin
#   Cleaning-Ops-Operator.command → :5175 operator
#   Cleaning-Ops-Owner.command    → :5174 portal, owner@cleanfine.ru
# сами поднимают dev-сервер, если он не отвечает; DRY_RUN=1 — показать URL
#   Cleaning-Ops-iOS-Admin/Operator.command     → flutter run на iOS-симуляторе,
#   Cleaning-Ops-Android-Admin/Operator.command → на Android-эмуляторе (AVD co-test):
#   поднимают API-стенд и устройство, автологин через --dart-define=AUTO_LOGIN_*;
#   iOS: API_HOST=localhost, Android: 10.0.2.2; выбор AVD: CLEANFINE_AVD=<имя>

# macOS-десктоп (CLEANFINE.app на прод; лончера пока нет — сборка вручную):
cd mobile/cleaning-ops-app && flutter build macos --release \
  $(for s in AUTH FILES CORE GPS TICKETS NOTIFICATIONS SCHEDULE MATERIALS CHAT; do \
      printf -- '--dart-define=API_%s_URL=https://cleanfine.ru ' $s; done)
rm -rf /Applications/CLEANFINE.app && cp -R build/macos/Build/Products/Release/CLEANFINE.app /Applications/

# prod k3s
ssh vps2
kubectl -n cleaning-ops get pods
kubectl -n cleaning-ops logs deploy/auth --tail=50

# e2e (локально, сервисы подняты)
cd test && npx playwright test --project=api

# проверка домена
curl -sI https://cleanfine.ru/
curl -s -X POST https://cleanfine.ru/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin","password":"admin123"}'

# бэкапы/мониторинг (vps2)
ssh vps2 bash -s < scripts/backup/restore-verify.sh   # дрилл восстановления
kubectl -n monitoring get pods                         # стек kps (Prometheus/Grafana)
```

**Push-канал на своём сервере (06.10):** вместо исключённого Firebase — **self-hosted ntfy** (`infra/k8s/ntfy.yaml`, маршрут `https://cleanfine.ru/ntfy` → StripPrefix → :8080). Адресат = **топик**: токен устройства генерирует клиент (`cf-<32hex>`, secure storage), регистрируется штатным `POST /api/notifications/device`; сервер публикует через **`NtfyPushSender`** (`PUSH_PROVIDER=ntfy` в configmap; локальный `.env` тоже ntfy, дефолт кода — mock для тестов). **Протокол: текст POST + заголовок `Priority`, в теле конверт `{"v":1,"t":заголовок,"b":текст,"d":{data}}`** — JSON-режим ntfy не работает через traefik (Content-Type теряется), кириллица не влезает в HTTP-заголовки, а ntfy отбрасывает незнакомые поля JSON. Клиент (`NtfyPushService` в `push_service.dart`) держит стрим `GET /<topic>/json`, показывает системный баннер (`flutter_local_notifications`, канал `cleanfine_main`, Android13 `POST_NOTIFICATIONS`), тап → существующая маршрутизация `pushRoute`; Android-сборке нужен **core library desugaring** (build.gradle). Живая проверка на эмуляторе: `delivered:1`, в шторке «Смена через 30 минут / Кабинет 215…». **Границы:** iOS — только пока приложение открыто (настоящий фон-пуш требует APNs/Apple Developer Program); фон на Android ограничен живым изолированным стримом (без foreground-service). **Ловушки:** ntfy запрещает `base-url` с путём и требует его при `attachment-cache-dir` (флаги не задаём); `--log-level` — ДО подкоманды `serve`; на телефоне топик переживает перевыпуск, мёртвые строки devices деактивируем SQL-ом; тесты чатов «Вчера/Сегодня» теперь фикстурируются «полднем» — «now − минуты» около 00:00 падало после полуночи; `flutter build ipa` требует `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, если xcode-select съехал на CommandLineTools.

**Сделано 08.10 (ночь): смена пользователя в мобильном приложении.** Два бага с симулятора iOS воспроизведены на сборке из `develop` и закрыты. (1) **Чужие данные после перелогина:** оператор с открытой сменой → «Выйти» → вход админа — «Сегодня» показывал смену/«Мои заявки» оператора. (2) **«Воскрешение» сессии:** после выхода профиль снова показывал «Администратор · admin». На живом стенде оказалось: токены в Keychain были бригадира, а `profileProvider` (`GET /auth/me`) просто не перечитывался. Операции с токенами в `SessionController` сериализованы.
